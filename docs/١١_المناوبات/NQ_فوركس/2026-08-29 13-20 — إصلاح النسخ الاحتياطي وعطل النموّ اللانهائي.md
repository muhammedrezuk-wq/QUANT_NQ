## ١) لماذا لم يكن يعمل — **ليس المسار**

`D:` كان موجودًا فعلًا (762 غيغا حرّة · قابل للكتابة · 46 ملفًّا سابقًا).
**السبب الحقيقيّ مقاس:**
```
#800 يشترك بـ SYS_DAY  ← مُطلِقه
نبضات #806 الحيّة:  SYS_DAY = 0   ← لم تنبض قط
```
`SYS_DAY` تنبض مرّة كل 24 ساعة، والنظام يُعاد تشغيله قبلها ⇒ **المُطلِق لا يصل
أبدًا.** آخر نسخة على `D:` كانت 24-08 — يوم بقي النظام شغّالًا طويلًا.

## ٢) 🚨 عطل النموّ اللانهائي — انفجر أمامي وأُوقف

عند أوّل تشغيل بعد تغيير المسار:
```
.snapshot.tbakxdyt.tmp   →  7.72 غيغابايت في 5 دقائق (13:07 → 13:12)
والخادم توقّف عن الاستجابة
```
**أوقفتُ كل العمليّات فورًا**، ونُقل الملفّ خارج المشروع (لم يُحذف) →
`Desktop\ملف لقطة عالق 7.7GB — 2026-08-29`.

### الجذر — نفس عطل الشريك (188 غيغا) ولم يكن مُصلَحًا عندنا

`governance/server.py`:
```python
root = ROOT.parent                    # جذر المشروع
_BACKUP_SKIP_TOP = {"venv", "var", "backups", ".git", …}
BACKUPS_DIR = DATA_ROOT / "backups"   # = forex_runtime/var/backups
```
**`forex_runtime` و`crypto_runtime` لم يكونا في قائمة التخطّي** — فالمسح يدخلهما،
و**تحتهما `var/backups` حيث تُكتب اللقطة نفسها** ⇒ يقرأ ملفّه وهو يكبر ⇒ نموّ
لا نهائي. وأسوأ: محتواهما **روابط Junction راجعة لجذر المشروع** (مُتحقَّق:
atoms · core · governance … كلّها Junction) ⇒ نسخ مزدوج لكل شيء.

**الإصلاح:**
```diff
  _BACKUP_SKIP_TOP = {
      "venv": …, "var": …, "backups": …,
+     "forex_runtime":  "روابط للجذر + var — لا أصل فيها، وتحتها مجلّد اللقطة",
+     "crypto_runtime": "روابط للجذر + var — لا أصل فيها، وتحتها مجلّد اللقطة",
  }
```
`governance/` خارج ختم النواة ⇒ التعديل مشروع.

## ٣) 🔴 غلطة ارتكبتُها — مسجَّلة كما هي

استبدلتُ المسار بتعبير نمطيّ `^(\s*backup_dir\s*:\s*).*$` — **فطال سطرين**:
واحدًا تحت `config:` (المقصود) و**واحدًا تحت `config_schema:`** (تعريف النوع).
فصار المخطّط `backup_dir: 'D:/…'` بدل `{type: string}` ⇒ **كسر المنيفست**:

```
FAIL: DISCOVERY_FAILURES
Forex root manifests: 232   (بدل 233)
config_schema غير صالح بنيويًا: 'D:/…' is not of type 'object','boolean'
```
**النظام رفض الإقلاع.**

**التصحيح:** استُعيد المنيفست من النسخة الاحتياطيّة التي أخذتُها قبل التعديل،
ثمّ نُفِّذ التغيير بمحلّل يميّز القسمين (`config` مقابل `config_schema`)
**ويرفض الكتابة إن لم يكن السطر المطابق واحدًا بالضبط**.

**الدرس:** لا استبدال نمطيّ أعمى في YAML — المفتاح نفسه قد يتكرّر في المخطّط
وفي القيمة. يُعدَّل بوعي البنية، ويُتحقَّق بعد الكتابة بتحليل الملفّ.

## ٤) ملفّات لُمست

**النسخ القديمة على `D:` باقية كما هي** — لم تُحذف.

## ٥) أثره على الشريك

⚠️ **عطل النموّ اللانهائي كان كامنًا في نسختنا** — ليس مُصلَحًا كما بدا من تقرير
الشريك. أي جهاز يشغّل `/gov/backup` قبل هذا الإصلاح **معرّض للانفجار نفسه**.

## ٦) ما بقي مفتوحًا

- **`SYS_DAY` لا تنبض** — النسخة تعتمد على آليّة اللحاق (`catchup`) لا على
  المُطلِق اليوميّ. **يعمل، لكن الجذر (نبضة اليوم) لم يُعالَج.**
- **ملفّ 7.7 غيغا** على سطح المكتب — **قرار حذفه للمالك**.
