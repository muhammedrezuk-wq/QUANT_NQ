# ورقة تنفيذ QUANT_NQ — Unified Trading Horizon Index v1.0
**(ورقة المالك — وصلت بمحادثة ٢٦-٠٨ · معادلاتها وقيمها وبنودها محفوظة حرفيًّا، والمتن السردي مضغوط بأمانة على أرقام المالك ذاتها — لا تصحيح ولا تغيير قيمة)**
**(ملاحظة البوّاب المؤرَّخة ٢٦-٠٨:** المعادلات §9–§41 نُفِّذت بمراحل الهجرة §61 التي رسمتها الورقة نفسها — ظلًّا أولًا، **ثم سرَت بأمر المالك «فعل» فجر ٢٦-٠٨** (Phase 4): صفّ اعتماد باسم كلمته، المولَّد يحكم عيارات القرار و166 وهستيريسيس 581، **ويد المالك بعد التفعيل تعلو المولَّد والإطفاء كبسة** — التفصيل بهندسة ١٧ §٦. المصدر الحي **مفتاح الأفق** `TRADING_HORIZON` (ورقة المفاتيح الأربعة فصلته عن السرعة)، والتحويل: مؤشر الورقة = 101 − المفتاح. سلَفاها — سكالبينغ v3.0 وسلسلة الـ20 — بأرشيف ٢٦-٠٨ لأن §2/§74 ينصّان على إحلالهما. وطبقة المخاطرة تبقى بعقد المحورين v1.1 §3 المختوم لا §13 القديمة.)**

**التاريخ:** 2026-08-25
**الحالة:** تصميم تنفيذي دقيق
**النطاق:** من `1.00` إلى `100.00` بدقة `0.01`
**الهدف:** استبدال سلالم Profiles المنفصلة بمؤشر واحد مستمر يولّد شخصية التحليل والتداول من أسرع Scalping ممكن إلى أفق طويل يمتد إلى أشهر.

# 1. القرار
يُعتمد متغير مركزي واحد: `TRADING_HORIZON_INDEX` · المجال `[1.00, 100.00]` · الدقة `0.01`.
```text
1.00   = أقصى سرعة وأقصر ذاكرة مسموحة
100.00 = أقصى أفق وأطول ذاكرة مسموحة
```
**المؤشر لا يمثل سرعة تنفيذ الأمر.** هو يمثل: **شخصية الأفق التحليلي والتشغيلي للنظام.**

# 2. لماذا لا نستخدم 100 Profile؟
بدل P05...P100 نستخدم INDEX مستمرًّا — `31.74` و`31.75` كلها قيم صالحة، ولا قفزة مصطنعة بين Profiles.

# 3. التطبيع
`x = (I − 1.00) / 99.00` ثم `x = clamp(x, 0, 1)` — فتكون I=1→x=0 · I=50.50→x=0.5 · I=100→x=1.

# 4. قاعدة التحويل الزمني
لا interpolation خطيًّا للزمن — الزمن يتوسع أسيًّا:
```text
H(x) = H_min × (H_max / H_min)^x
H_min = 0.25 ثانية · H_max = 15,552,000 ثانية (= 180 يومًا ≈ 6 أشهر)
```
فيغطي المجال: micro-tick → seconds → minutes → hours → days → weeks → months.

# 5. `1.00` لا يعني «تِكة واحدة حرفيًا»
يعني أقصر أفق عملي يسمح به عقد البيانات والمعادلات؛ الحدود الدنيا لكل محلل تبقى محترمة.

# 6–7. تحويل الزمن إلى عدد الملاحظات
`λ = observations_per_second` من البيانات الحية، ثم `N(T) = ceil(T × λ)` مع `N_final = clamp(N, N_min, N_max)`. وللتِكّات: `required_ticks = ceil(target_horizon_seconds × observed_tick_rate)` مع حد أدنى `atom_min_ticks` — السوق السريع لا يقصّر المؤشر خطأً والهادئ لا يترك المحلل بلا بيانات.

# 8. الذاكرة
`memory_factor = x^γ` مع `γ = 1.35` — أول المجال يبقى سريعًا جدًّا والانتقال للآفاق الطويلة بلا قفزة.

# 9. 166 — وزن المسارات
```text
fast_weight = 90.0 − 25.0 × x · slow_weight = 100 − fast_weight
I=1 → 90/10 · I=50.5 → ≈77.5/22.5 · I=100 → 65/35
```
حتى عند الأفق الطويل لا نلغي الـFast Path، وحتى عند الـScalping لا نلغي الـSlow Path.

# 10. 166 — الطزاجة (الصيغة المعتمدة)
```text
stale = 1.5 + 4.5 × x        ⇒ I=1 → 1.5s · I=100 → 6.0s
```
(الصيغة المعكوسة 6.0−4.5x مرفوضة — الأفق الطويل لا يجعل stale أصغر.)

# 41–44. 581 والفصل
`s_enter = 0.35 + 0.03x` · `s_exit = 0.20 + 0.05x`. منحنى E/H الست نقاط (0/0.08/0.18/0.30/0.42/0.50 · H من 1.00 إلى 0.20) **ثابت في الإصدار الأول** — لا نخلط سرعة الأفق مع قوة الاتجاه: `I` يحدد كيف يفكر النظام و`S` كم قوة الدليل، ولا يجوز دمجهما.

# 45. 811
تستمر بلا تغيير — تقيس ولا تعرف شيئًا عن توليد Profile.

# 46–48. الاختبار
Coarse scan على 1/10/.../100 ثم تضييق النطاق الأفضل حتى `31.72، 31.73...` بلا ورقة جديدة. الاختيار بscore خارجي (activity/stability/persistence − jump/reversal/stale penalties) **لا يدخل القرار الحي**.

# 49–50. الحوكمة
`Index = owner-selected` لا self-adjusting في الإصدار الأول؛ والتكيف (820→840→850) إصدار لاحق.

# 51–52. المخاطر
المؤشر لا يغير ميزانية الخطر — `R_B` للمالك، و`I → تحليل الشخصية · S → قوة الإشارة · R_B → قدرة المخاطرة` ولا اختصار `I → lot`.

# 53–55. السلامة والدقة والمصدر
خارج [1,100] ⇒ `INVALID_PROFILE_INDEX` ولا يُعدَّل عيار · `round(I, 2)` قبل التوليد · كل Configuration تسجل `profile_index · profile_version · generated_at · formula_version`.

# 56–59. مصدر الحقيقة والحدود
`OWNER INDEX → 523 Profile Engine → Generated Config → governed dial store → atoms` ولا تنشئ الذرات Profileها الخاص. المؤشر يتحكم فقط بالمصنَّف `HORIZON_DEPENDENT` (القائمة الكاملة في §58 بنص المالك: نوافذ 151/152/153/155/162/163/165 + 166 + 452/453/458/413/455-456 + 523 + 581 hysteresis)؛ والثابت خارج المحرك: الحساب والوسيط والرمز والعقود وقواعد الهامش والصلاحيات وشرعية الوقف الصلبة و`R_B` وحدود الخسارة والحوكمة والدوام وهوية الجسور.

# 60–61. الهجرة
لا يُحذف `default_dial` فورًا — `legacy_dial = compatibility layer` ثم `profile_index = source of truth` ولا يبقى مساران للحقيقة. المراحل: **Phase 1 ظل → Phase 2 يولد config → Phase 3 مقارنة بالقديم → Phase 4 تفعيل → Phase 5 القديم deprecated.**

# 62–64. أمثلة
`I ≥ 70` لا يعني دخول السوق على أساس أشهر — التحليل أطول أفقًا فقط والقرار والتنفيذ لهما بوابات مستقلة. `I=24.50`: fast-heavy قصير الذاكرة طازج البيانات · `I=35.75`: سكالب أثبت · `I=55.20`: يقترب من intraday أطول — بلا Profile جديد. ونفس السوق يُقرأ scalp عند I=10 وintraday عند I=40 وأطول عند I=70 — وهذا هو الهدف.

# 65–69. التحقق
اختبار I على 1/10/.../100 وقراءة كل المولَّد · **اختبار monotonicity**: I↑ ⇒ Horizon لا ينخفض، Fast لا يرتفع، النوافذ لا تنخفض، الإيقاع لا يتسارع — وإلا `PROFILE_MONOTONICITY_ERROR` · اختبار الحدود عند الطرفين ولا تجاوز لحدود الذرة/الوسيط/المانيفست · 811 لكل Index ثم منحنى INDEX→QUALITY · والاختيار: أسرع Index لا يزال مستقرًّا وقابلًا للتحليل.

# 70–74. النتيجة
بدل «استخدم P40» يقول المالك: `TRADING_HORIZON_INDEX = 34.72` وQUANT_NQ يولد بقية الشخصية. اللوحة: عنصر واحد للإدخال وتحته قراءة Read-only (الأفق، المساران، الطزاجة، الزخم، السرعة، المتوسطان، الإيقاع، نطاق الحياد). كل تغيير `34.72 → 34.73` يعامل كتغيير Profile: `validate → version → publish → hot-load → measure` ولا يُسمح بتغيير نصف configuration. `PROFILE_ENGINE_VERSION = 1.0.0`.

# 75–76. القرار التنفيذي النهائي
**يعتمد:** المجال المستمر بدقة 0.01 · الأفق اللوغاريتمي · التحويلات لكل عيار · تحقق الرتابة · قياس 811 · اختيار المالك. **ولا يعتمد:** أي ضبط ذاتي أو تحسين ربح آلي أو تغيير R_B آلي أو عدوانية تنفيذ آلية — في الإصدار الأول.
والتسميات (tick→micro-scalp→scalp→...→months) **وصفية فقط**؛ الزمن الفعلي يحدده `H(x)` والعيارات تُولَّد من `x` بدوالها.
**هذا هو التصميم الصحيح إذا كان المطلوب تحويل QUANT_NQ من مجموعة Profiles ثابتة إلى محرك أفق مستمر واحد قابل للمعايرة حتى منزلتين عشريتين.**
