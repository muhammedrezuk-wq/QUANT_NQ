# دستور النظام — وصف المالك الكامل بالمعادلات (٢٠٢٦-٠٨-١١)

> **هذه الورقة نصّ المالك حرفياً كما أملاه بتاريخ ٢٠٢٦-٠٨-١١.**
> هي المرجع الأعلى لفهم النظام وقياس أي بناء أو تصليح لاحق عليه.
> لا يُعدَّل فيها حرف إلا بأمره. أي تعارض بين الكود وهذه الورقة = عطل في الكود.

وصف نظام QUANT_NQ بالكامل

الفكرة الأساسية أن النظام لا يتعامل مع الصفقة كشيء منفصل، بل يتعامل مع كل أصل مالي كحالة مستمرة.

مثلاً:

```text
BTCUSD
```

له ميزانية مخاطرة مستقلة، وحالة مستقلة، ومراكز مستقلة، وسجل أرباح مستقل.

إذا كان:

```text
BTCUSD = R_B 100$
XAUUSD = R_B 50$
NAS100 = R_B 50$
```

فكل أصل يعمل لوحده. ربح أو خسارة الذهب لا يغيّر ميزانية ناسداك.

## 1. بداية الأصل

عند تشغيل أصل جديد، لا يدخل النظام مباشرة شراء أو بيع.
البداية تكون:

```text
BUY + SELL
```

بحجم متساوٍ تقريبًا.
يعني:

```text
V_buy = V_sell
```

وبالتالي:

```text
V_net = V_buy - V_sell = 0
```

وهذه تسمى:

```text
NEUTRAL
```

الفكرة أن النظام يدخل السوق وهو محايد، وبعدها التحليل هو الذي يحدد أي جهة يبدأ بتوسيعها.

## 2. ميزانية الأصل

لكل أصل:

```text
R_B = ميزانية مخاطرة الأصل
```

مثلاً:

```text
R_B = 50$
```

هذه ليست نسبة من Equity الحساب.
وليست:

```text
1% من الحساب
```

بل رقم مستقل ثابت للأصل حسب إعداداته.

## 3. حساب حجم البداية

النظام يحسب المسافة النظرية للحماية:

```text
stop_distance = price × stop_distance_frac
```

ثم قيمة الخطر لكل لوت:

```text
risk_per_lot = stop_distance × vpu
```

حيث:

```text
vpu = tick_value / tick_size
```

ثم:

```text
lot_raw = R_B / risk_per_lot
```

ويتم تقريب الحجم حسب مواصفات الوسيط:

```text
lot_steped =
round(lot_raw / volume_step) × volume_step
```

ثم:

```text
lot_final =
min(max_lot,
    max(0, lot_steped))
```

ومن هنا تكون البداية:

```text
BUY(lot_final)
+
SELL(lot_final)
```

## 4. من أين يأتي القرار؟

النظام لا يسمح لأي استراتيجية أن تقول مباشرة:

```text
BUY
```

أو:

```text
SELL
```

وتفتح صفقة.
الاستراتيجيات والمحللات تعطي أدلة فقط.

السلسلة:

```text
الأسعار
↓
التحليلات
↓
451 تجميع الإشارات
↓
452 تقييم الإشارات
↓
453 تحويلها إلى درجات
↓
458 حل التعارض
↓
الاتجاه
↓
قوة الاتجاه
↓
المركز المطلوب
```

يعني عندك مثلاً عدة أدلة تقول:

```text
BUY قوي
BUY متوسط
SELL ضعيف
```

محرك القرار يجمعها ويخرج:

```text
الاتجاه = BUY
القوة S = 0.78
```

أما لو كانت الأدلة متضاربة:

```text
BUY = 0.51
SELL = 0.49
```

فلا يوجد سبب لفتح تعرض كبير.

## 5. قوة الاتجاه

القوة `S` بين:

```text
0 → 1
```

وتتحول إلى نسبة تعرض:

```text
S < 0.20        → 0%
0.20 ≤ S < .40 → 10%
0.40 ≤ S < .60 → 25%
0.60 ≤ S < .75 → 50%
0.75 ≤ S < .90 → 70%
S ≥ .90         → 100%
```

يعني مثلاً:

```text
S = 0.78
```

يعطي:

```text
f(S) = 0.70
```

أي أن النظام لا يقفز مباشرة إلى أقصى مركز.
يبني التعرض تدريجيًا.

## 6. كيف يقرر كم يشتري؟

أقصى تعرض ممكن:

```text
capacity =
min(
    max_target_volume,
    R_B /
    (price × stop_distance_frac × vpu)
)
```

ثم:

```text
target_net =
+capacity × f(S)
```

إذا الاتجاه BUY.
أما SELL:

```text
target_net =
-capacity × f(S)
```

أما:

```text
NEUTRAL
WAIT
```

فيكون:

```text
target_net = 0
```

وهنا بالضبط يصير الشيء الذي كنت تريده:
كلما زادت قوة الاتجاه، النظام يزيد التعرض تدريجيًا.

## 7. كيف يزيد المركز بدون تكسير النظام؟

النظام لا يقول:
افتح صفقة جديدة.
بل يقارن:

```text
الموجود فعليًا
```

مع:

```text
المطلوب
```

لدينا:

```text
current_buy
current_sell
```

ولدينا:

```text
target_buy
target_sell
```

ثم نحسب الفرق:

```text
delta_buy =
target_buy - current_buy
```

و:

```text
delta_sell =
target_sell - current_sell
```

إذا كان:

```text
delta_buy > 0
```

فالمطلوب زيادة BUY.
إذا:

```text
delta_buy < 0
```

فالمطلوب تخفيف BUY من المركز الموجود نفسه.
ونفس الشيء للـSELL.

## 8. لماذا يوجد رجلان دائمًا؟

لأن النظام لا يتحول من:

```text
BUY → SELL
```

بقفزة واحدة.

مثلاً لديك:

```text
BUY 60
SELL 0
```

والتحليل تغيّر وأصبح المطلوب:

```text
BUY 40
```

مع المحافظة على إجمالي المركز:

```text
target_gross = 60
```

فتصبح:

```text
target_buy  = 50
target_sell = 10
```

فيصدر:

```text
BUY -10
SELL +10
```

أي:

```text
CLOSE_PARTIAL BUY 10
OPEN SELL 10
```

فتصبح:

```text
BUY 50
SELL 10
```

وصافي التعرض:

```text
50 - 10 = +40
```

يعني ما زلنا BUY، لكن النظام بدأ يحمي نفسه ويجهز للتحول.

## 9. الانتقال من BUY إلى SELL

التحول ليس:

```text
CLOSE_ALL
OPEN SELL
```

بل تدريجي.
مثلاً:

```text
BUY 60 / SELL 0
```

ثم:

```text
BUY 50 / SELL 10
```

ثم:

```text
BUY 30 / SELL 30
```

ثم:

```text
BUY 10 / SELL 50
```

ثم:

```text
BUY 0 / SELL 60
```

وبالتالي:

```text

↓
تحوط
↓
NEUTRAL
↓
تحوط بالجهة الأخرى
↓
SELL
```

وهذا هو جوهر النظام.

## 10. التحوط ليس إغلاق الأصل

إذا بدأ الاتجاه ضدنا، لا يعني ذلك:

```text
أغلق الأصل
```

بل:

```text
خفف التعرض
وزد الرجل المقابلة
```

حتى يصل:

```text
V_net = 0
```

أي:

```text
NEUTRAL
```

ثم إذا استمر الاتجاه المقابل، يبدأ النظام بتوسيع SELL.

## 11. إذا فشلت رجل التحوط

هذه نقطة مهمة جدًا.
مثلاً النظام يريد:

```text
CLOSE BUY
OPEN SELL
```

لكن:

```text
SELL = REJECT
```

فلا يغلق النظام الرجل الناجحة ويعتبر المهمة انتهت.
بل يحتفظ بالـBUY ويربط العملية:

```text
pair_id
leg_role
attempt
ACK
REJECT
ACTUAL
```

ثم يعيد محاولة الرجل الفاشلة فقط.
إذا انتهت المحاولات بدون اكتمال التحوط:

```text
ESCALATE
↓
FREEZE
```

ولا يبدأ النظام بالتخمين.

## 12. المخاطر أثناء التشغيل

النظام يحسب الأثر الاقتصادي الحقيقي.
لكل مركز:

```text
floating_i =
(close_price - entry_price)
× s_i
× volume
× vpu
```

حيث:

```text
s = +1 BUY
s = -1 SELL
```

والتكاليف:

```text
cost_i =
commission
+
swap
+
estimated_close_commission
```

ثم:

```text
economic_i =
floating_i - cost_i
```

و:

```text
E = Σ economic_i
```

## 13. الربح المحقق

لدينا:

```text
G = الربح الإجمالي المحقق
```

والربح الصافي المعلوم:

```text
N_R =
Σ(profit - commission - swap)
```

أما المبلغ الذي بقي داخل النظام:

```text
K = max(0, G - X)
```

حيث:

```text
X = التخريج الذي تم تنفيذه فعليًا
```

وليس التخريج الذي طلبناه فقط.

## 14. لماذا K مهم؟

لأنك تريد أن ينمو النظام من أرباحه بدون المساس بالأساس.

الحالة الاقتصادية:

```text
state_net = K + E
```

والخطر:

```text
loss_exposure =
max(0, -state_net)
```

ثم:

```text
u =
loss_exposure / R_B
```

إذا:

```text
u = 1
```

يعني استهلك النظام ميزانية الأصل كاملة.
ليس معناه أن الحساب كله خسر 1%.

## 15. مستويات الخطر

لدينا:

```text

```

و:

```text

u ≥ 1.00
```

عند التحذير أو التحوط:

```text

```

لكن:

```text

```

وعند:

```text

```

```text

```

ولا يسمح بزيادة جديدة.

## 16. وقف P0

للمركز غير المحايد:

```text
room = R_B + K - commission_est
```

و:

```text
delta_price =
room /
(vpu × abs(V_net))
```

ومتوسط الدخول:

```text
average_entry = W / V_net
```

حيث:

```text
W =
Σ(s × volume × entry_price)
```

والستوب:

إذا:

```text
V_net > 0
```

أي BUY:

```text
p_stop =
average_entry -
room / (vpu × V_net)
```

وإذا:

```text
V_net < 0
```

أي SELL:

```text
p_stop =
average_entry +
room / (vpu × abs(V_net))
```

أما:

```text
V_net = 0
```

فلا يوجد وقف اتجاهي وهمي.

## 18. سلم الأرباح

عندك سلم مستقل:

```text
50
100
200
400
800
...
```

المعادلة:

```text
M_k = R_B × 2^k
```

ونصف المستوى يخرج:

```text
X_k = 0.5 × M_k
```

مثلاً عند:

```text
R_B = 50
```

يكون:

```text
50  → إخراج 25
100 → إخراج 50
200 → إخراج 100
400 → إخراج 200
```

المجموع:

```text
X = 25 + 50 + 100 + 200
  = 375
```

وعند الوصول إلى 400:

```text
K = 400 - 375
  = 25
```

فيبقى:

```text
50$ أساس
+
25$ نمو داخل النظام
=
75$
```

## 33. ما الذي يتعلمه النظام؟

يسجل مثلاً:

```text
ماذا رأى السوق؟

الثقة
السعر
المركز
القرار

الربح
الخسارة

أكبر خسارة عائمة

```

ثم بعد عدد كافٍ من الحالات يستطيع قياس:

```text

متى تعمل الإشارة
متى تفشل
هل النموذج يتدهور
```

```text

```

## 34. حالات الأصل

الأصل يتحرك ضمن حالات واضحة، مثل:

```text
NEUTRAL
BUY
SELL
WARNING
HEDGING
REBALANCING
FROZEN
PAUSED
```

والفكرة أن الحالة لا تنتهي بمجرد انتهاء صفقة واحدة.
إذا تغيرت السوق:

```text
BUY
↓
HEDGING
↓
NEUTRAL
↓
SELL
```

الحالة تستمر.
