# ورقة المحورين v1.1 — الواقع والهدف والفرق
**التاريخ:** 2026-08-25 مساءً · **الحالة:** ✅ **عقد مرحلة 1 مختوم `NQ`** — «هذه النسخة من منطق الـRisk Dial معتمدة مني كمرجع مرحلة 1. NQ» · **تحل محل:** Target State v1.0 (محفوظة للأرشيف) · **التنفيذ بعد إنهاء المرحلة 0 (جدار الثقة) حصرًا**
**القاعدة الحاكمة:** الواقع من الكود أولًا · الدليل القديم ليس مرجعًا إذا خالف الكود · CURRENT ≠ TARGET

> **(تنفيذ ٢٦-٠٨ ليلًا — بأمر المالك المباشر «بدي ورقة تتنفذ وتتقفل»، ناقضًا شرط «بعد المرحلة 0» أعلاه بكلمته):**
> **المرحلة 1 (§3) نُفِّذت كاملة وأُقفلت:** عيار `RISK_DIAL` محكوم في سجل العيارات (بدء **100** = سلوك اليوم بلا تغيير، حتى يضبطه المالك بيده من اللوحة عبر 901) · المعادلة المختومة حرفيًّا في 581 v3.4.0 (`shared/position_delta_recompute.py`) مع تحذير المبرمج فوق الكود · محاسبة الميزانيات الثلاث تُنشر مع كل هدف · 707 v4.2.0 يسجّلها واللوحة تعرضها (بطاقة الهدف بقسم التنفيذ) · فحوص القبول المختومة §3-ج خضراء (`test_risk_dial.py`) والأسطول 788 بلا تراجع.
> **ترتيب §3-د بعدها:** البند 1 منجز — والبنود 2 (قياس 811) و3 (تثبيت) و4 (ورقة Horizon) **لم تبدأ**.

## ٠ · حسم المالك (مختوم — لا يعاد فتحه)

1. **الدايل يطبَّق مرة واحدة فقط:** `D = RISK_DIAL/100` يضرب **التعرض الجديد** بعد عامل التحليل:
   `target_new_exposure = base_target_exposure × D` — ولا يدخل D في E(S) ولا في السعة مرة ثانية. (يقتل تربيع v1.0 بين §13 و§20.)
2. **دايل صفر يمنع الجديد ولا يصفّي القائم:** `Dial=0 ⇒ NO_NEW_EXPOSURE` والهدف لا ينزل تحت المركز القائم بحكم عقد 581 — **الدايل يتحكم في الزيادة لا في البقاء**. (متوافق مع فلسفة المركز الدائم ومع حكم التعرض المنفَّذ في 508 v3.1.0.)
3. **الأولوية الرسمية:** `الثقة → Risk Dial → قياس 811 → فصل Horizon` — **ولا يُكتب عقد تنفيذ للـHorizon قبل إنهاء جدار الثقة.**

## ٣ · مواصفة المرحلة 1 — Risk Dial (العقد الوحيد القابل للتنفيذ الآن، بعد إنهاء الثقة)
**(§3 معدَّلة بتصحيح المالك ٢٥-٠٨ مساءً: فصل الزيادة عن الخفض — صيغة `max(current, raw) if D_dropped` القديمة ملغاة لأنها كانت تعطّل خفض التحليل الطبيعي عند ثبات D.)**

1. عيار `RISK_DIAL` في سجل العيارات المحكوم (DECLARED) بمجال [0,100] وقيمة بدء يقررها المالك؛ يضبط من اللوحة عبر 901 (نفس مسار decision_setting) ولا يتكيف تلقائيًّا.
2. **المعادلة التنفيذية النهائية (نصّ المالك الحرفي — مختومة `NQ`):**
   ```
   D                = RISK_DIAL / 100
   base_target      = min(capacity_full × E(S), gross_cap)
   increase         = max(0, base_target − current_gross)
   allowed_increase = min(increase, capacity_full × E(S) × D)
   decrease         = max(0, current_gross − base_target)      # الخفض يتبع التحليل وحده — لا يخضع لD أبدًا
   gross_target     = current_gross + allowed_increase − decrease
   ```

3. **التحذير اللفظي للمبرمج (نصّ المالك — يُنسخ فوق الكود):**
   ```
   RISK_DIAL
   = بوابة لنمو التعرض الجديد
   ≠ بوابة للبقاء
   ≠ عامل في E(S)
   ≠ عامل في gross_cap
   ≠ عامل في R_B
   ```

3-ب. **دلالة الاختيار المختوم (مُعلنة لا مخفية):** بهذه الصيغة D يحدّ **مقدار النمو في كل دورة قرار** (وليس مستوى التعرض المستقرّ): أي D>0 يبلغ المركزُ معه كاملَ base_target عبر دورات متتالية — D=0.25 يبلغه في ~4 دورات، D=0.5 في دورتين. هذا متسق مع فلسفة v1.0 §37-39 (البناء التدريجي، لا قفز الحجم)؛ **وتنبيه إيقاع مقيس:** «الدورة» = إعادة حساب 581 لكل قرار عابر للبوابة، وإيقاع القرارات عندنا بالثواني — فعمليًّا أي D>0 يبلغ الهدف الكامل خلال ثوانٍ إلى دقائق ما دام التحليل ثابت القوة، وكابح المستوى الوحيد يبقى R_B/gross_cap وبقية الحواجز. اختبار v1.0 §64 القديم (المستويات المستقرة المتدرجة) **منسوخ بهذا الختم** وتحل محله حالات المالك أدناه.

3-ج. **حالات القبول المختومة (نصّ المالك):**
   ```
   D = 0   → allowed_increase = 0 → لا فتح/إضافة جديدة → ولا تصفية للمركز القائم بسبب الـDial
   D = 25  → يسمح بـ25% من الزيادة الممكنة (في الدورة)
   D = 50  → يسمح بـ50%
   D = 100 → يسمح بكل الزيادة التي تسمح بها E(S) + R_B + gross_cap + بقية الحواجز
   S ينخفض → base_target < current_gross → decrease > 0 → التخفيض مسموح حتى لو D = 0
   ```

4. **محاسبة الميزانيات (تسميات المالك المعتمدة):**
   ```
   consumed_budget      = max(u_float, u_realized) × R_B     # من حقلي 518 المنفصلين، لا من u المنشور
   remaining_RB         = R_B − consumed_budget               # المتبقي من السقف الأصلي
   dial_add_budget      = R_B × D − consumed_budget           # ميزانية الإضافة بحكم الدايل
   remaining_add_budget = max(0, dial_add_budget)             # ≤ 0 ⇒ لا دلتا موجبة
   ```
5. **موضع D:** عند 581 فقط (تحديد كم تعرض جديد يُسمح) — لا يدخل بعد Room ولا بعد Size ولا في أي بوابة لاحقة.
6. 707 يسجل: risk_dial, base_target, gross_target, target_net, remaining_RB, dial_add_budget, remaining_add_budget. اللوحة تعرضها.
7. **اختبارات القبول:** حالات المالك المختومة في §3-ج (تنسخ §64 القديم) + بقية اختبارات v1.0 (§54-63) حيث لا تتعارض + مثال الخفض: current=10, S: 0.80→0.30, D=50 ⇒ الهدف ينزل لbase الجديد.
