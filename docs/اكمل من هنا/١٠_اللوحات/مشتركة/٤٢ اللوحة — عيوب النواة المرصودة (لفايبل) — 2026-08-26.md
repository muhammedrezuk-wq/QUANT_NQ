# ١ · ع-٥ — heuristic الإعادة بالناقل

## ما هو
الناقل يصنّف اسم الحدث بمطابقة **احتواء جزئي** لا بحدود كلمات. أي اسم حالة تصادف أن يحوي سلسلة من `_COMMAND_MARKERS` يُصنَّف «أمرًا» ⇒ **لا يُخزَّن ولا يُعاد** للمشترك المتأخّر.

## الدليل

`core/event_bus.py:85`
```python
_STATE_SUFFIXES = (".state", ".synced", ".snapshot")
```

`core/event_bus.py:91-94`
```python

    "order", ".buy", ".sell", ".execute", ".cancel",
    "final_decision", "command", ".submit", ".send",
)
```

`core/event_bus.py:109-110` (داخل `_classify_name`)
```python
        command = any(marker in event_name for marker in _COMMAND_MARKERS)
        replayable = event_name.endswith(_STATE_SUFFIXES) and not command
```

ومواضع الاستهلاك الثلاثة:

- `core/event_bus.py:501-502` — التخزين للإعادة:
  ```python
        if _is_replayable(event_name):
            self._last_event[event_name] = _isolated_copy()
  ```
- `core/event_bus.py:392-398` — إعادة آخر حالة للمشترك الجديد (`subscribe`).
- `core/event_bus.py:446-453` — إعادة كل الحالات المخزَّنة لمشترك الـfirehose (`subscribe_all`).

**ومن هو مشترك الـfirehose؟** اللوحة نفسها — `core/api/app.py:268`:
```python

                            isolate_payload=False)
```
أي أنّ كل حدث لا يدخل `_last_event` **لا يصل لوحة تُفتح متأخّرة**، ولا يظهر إلا عند النشرة الحيّة التالية.

## أثران إضافيّان لم يردا بالرصد السابق
نفس التصنيف يُستعمل في موضعين آخرين، فالضرر مضاعَف لا واحد:

1. **لا دمج (`LATEST_ONLY`)** — `core/event_bus.py:253`:
   ```python
        if _is_replayable(event_name):
   ```
   الحالة المصنَّفة «أمرًا» لا تُدمَج، فالمستهلك البطيء يقرأ **طابور ماضٍ** بدل آخر حقيقة.
2. **صندوق بريد بلا سقف** — `core/event_bus.py:264-267`:
   ```python
        if not _is_command(event_name):
            while len(box.queue) >= self._mailbox_max_events:
                oldest = box.queue.popleft()
                self._dropped[str(oldest[1])] += 1
   ```
   الحالة المصنَّفة «أمرًا» **لا تُسقَط أبدًا** من صندوق ممتلئ ⇒ نموّ ذاكرة بلا حدّ إن تباطأ مستهلكها. وهذا **عكس** نيّة الحارس: القصد حماية الأوامر الحقيقيّة، فورث الحمايةَ حدثُ حالة بالخطأ.

## القائمة الكاملة — كل حدث ينتهي بـ`.state`/`.synced`/`.snapshot` ويحوي مؤشّرًا
مطبَّقة نصًّا على الجرد الكامل (`publishes` + `subscribes` في ٢٣٠ مانيفست)، ومؤكَّدة بمسحين مستقلّين:
1. مسح سلاسل الكود في `atoms/ core/ transport/ shared/ ctrader/ mt5/ runtime/ tools/` — **١٨٣** اسم حالة فريد.
2. مسح أوسع على الشجرة كلّها بلا استثناء (`.py` · `.yaml` · `.json` · `.md`، شاملًا `venv/` و`docs/` و`سياق/`) — **١٨٥** اسم حالة فريد.

الأربعة الأخرى أقلّ حدّة: مشتركوها ذرّات تقلع مع النظام لا لوحة متأخّرة، لكنّها تفقد الإعادة عند **إعادة تحميل ساخنة لذرّة واحدة** (`core/hot_reload_service.py:388,459` يعيد بناء الاشتراكات) — فذرّة 458 أو 254 المعاد تحميلها تبقى بلا آخر أهليّة/سيولة حتى النشرة التالية، بينما نظيراتها غير المؤشَّرة تستلمها فورًا.
