# هندسة QUANT_NQ

هذا الملف يشرح أين يعيش كل شيء ولماذا، حتى لا يبحث المطور أو النموذج بين عشرات الملفات.

---

## 1. خريطة الجذر

| المجلد | وظيفته | هل هو تشغيل؟ |
|---|---|---:|
| `core/` | النواة والعقود العامة | نعم |
| `build_registry/` | سجل اكتشاف البناء المركزي | نعم، قراءة واكتشاف فقط |
| `shared/` | عقود وخدمات مشتركة | نعم |
| `atoms/` | ذرات الفوركس | نعم |
| `atoms_crypto/` | ذرات الكريبتو | نعم |
| `governance/` | الفحوص والحوكمة واللوحة | نعم |
| `transport/` | نقل وملكية الأحداث | نعم |
| `security/` | خزنة الأسرار ومزوّداتها | نعم |
| `clock/` | عقد الوقت الخارجي/الموحد | نعم |
| `catchup/` | عقود اللحاق بالأرشيف | نعم |
| `storage_policy/` | سياسات التخزين | نعم |
| `config/` | إعداد Core وعقد الإصدار | نعم |
| `runtime/` | قوالب runtime، بلا أسرار فعلية | بيانات تشغيلية |

## 2. Core

Core لا تنفذ Trading ولا Decision. أهم وحداتها:

```text
core/contracts/       العقود
core/bootloader.py    اكتشاف وتحميل ودورة حياة الذرات
core/manifest_loader.py  اكتشاف manifest متكرر
core/event_bus.py     ناقل الأحداث
core/health_manager.py الصحة والتعافي
core/hot_reload_service.py التغيير الحار
core/registry.py      حالة الذرات
core/snapshot_engine.py اللقطات
core/api/app.py       API خام عامة
```

Core مختومة بـ`CORE.lock`، وأي تغيير معماري يرفع الإصدار ويعيد الختم.

---

## 3. Build Registry

```text
build_registry/
├── models.py
├── discovery.py
├── registry.py
├── contracts.py
├── paths.py
└── README.md
```

هو سجل قراءة واكتشاف:

```text
لا يشغّل ذرة
لا يوقف ذرة
لا يغير manifest
لا يختار Build عند التعارض
```

هو مصدر lookup للهوية:

```text
find_atom(578) → المسار الحقيقي مهما كان عمقه
```

والأدوات القديمة تستعمل `RegistryAtomRoot` كطبقة توافق إلى أن تُنقل كليًا إلى API المركزية.

---

## 4. الذرة

كل مجلد ذرة يحتوي عادةً:

```text
atom.py
manifest.yaml
tests/test_atom.py
الشرح.md  (إن توفر)
التاريخ.md (إن توفر)
```

الكود لا يستورد كود ذرة أخرى. الذرات تتخاطب بالأحداث.

---

## 5. Shared

Shared ليس Domain رابعًا للتداول، وليس جزءًا من عداد Forex أو Crypto. هو مكان:

```text
contracts
identity
financial truth
snapshot
journal
learning interfaces
parameter interfaces
```

كل خدمة مشتركة يجب أن تملك عقدًا واضحًا ولا تحمل قرارًا مخفيًا لنطاق واحد.

---

## 6. Governance

Governance عملية منفصلة تقرأ Core وتعرض الحقائق وتنفذ الفحوص. لا تكون مصدر الحقيقة للذرات.

```text
go​​vernance/checks/   فحوص العقود
 governance/scripts/  أدوات تشغيل وإثبات
go​​vernance/ui/       اللوحة
go​​vernance/server.py خادم اللوحة
```

سياسات Domain موجودة في adapters الحوكمة، لا داخل Core العامة.

---

## 7. Forex وCrypto

كل نطاق له:

```text
root منفصل
config منفصل
runtime منفصل
API port منفصل
journal/snapshot منفصل
```

الفوركس:

```text
atoms/
config/core_forex.yaml
forex_runtime/
```

الكريبتو:

```text
atoms_crypto/
config/core_crypto.yaml
crypto_runtime/
```

لا يوجد import مباشر بين Atom فوركس وAtom كريبتو.

---

## 8. النقل والأحداث

`transport/` يطبق ملكية وتوزيعًا منخفض النسخ عند الحاجة. `core/event_bus.py` يطبق العقد العام للمهلة والعزل والحالة. لا يحق لمشترك بطيء تجميد بقية المشتركين.

---

## 9. الأمن

```text
security/       كود الخزنة
runtime/        قالب/مكان تشغيل
var/            بيانات runtime غير مسلّمة
```

الخزنة غير مهيأة في النسخة الحالية. لا تُكتب قيم المفاتيح في الكود أو التقارير أو ZIP.

---

## 10. الاختبارات

```text
tests/core/          Core/lifecycle/hot reload
 tests/              اختبارات المسارات والذرّات
 atoms/.../tests/    اختبار الذرة نفسها
```

الاختبارات تستخدم Registry عند الوصول إلى Atom داخل مجلدات الأقسام. لا يُسمح بإرجاع المسارات القديمة إلى الجذر.

---

## 11. قواعد المجلدات

- لا تضع تقريرًا عشوائيًا في الجذر.
- لا تضع قاعدة بيانات runtime داخل المصدر.
- لا تكرر نسخة من Atom في مجلد آخر لإرضاء اختبار.
- لا تجعل الأرشيف نافذًا.
- كل شرح مؤسسي يذهب إلى ملف الموضوع الجامع تحت `docs/`.
- كل كود يبقى مع الطبقة التي تملكه.
