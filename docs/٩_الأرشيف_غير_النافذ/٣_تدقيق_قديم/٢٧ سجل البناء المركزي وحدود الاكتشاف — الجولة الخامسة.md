# سجل البناء المركزي وحدود الاكتشاف — الجولة الخامسة

**التاريخ:** 2026-08-27  
**نوع الجولة:** تنفيذ Gate 01 → 07 فقط.  
**الحالة:** تم إنشاء Registry واختباراته، ثم التوقف قبل Lifecycle/Release migration.

---

## 1. ما نُفّذ

```text
01 Build Registry
02 Recursive Discovery
03 Root unification
04 Build metadata resolution
05 Shared classification
06 Governance 901+ classification
07 Execution Target Discovery
```

المكوّن الجديد هو:

```text
build_registry/
```

وهو خارج `core/` حتى لا يفتح ختم `CORE.lock` في هذه الجولة.

---

## 2. قاعدة الاكتشاف

`build_registry.discovery` يستخدم عقد الاكتشاف المتكرر الحالي:

```text
core.manifest_loader.scan()
```

والـRegistry لا يستخدم مسارًا مباشرًا مثل:

```text
glob("578_*")
```

المعرّف أصبح lookup منطقيًا:

```text
BuildRegistry.find_atom(578, scope="forex")
```

والنتيجة الفعلية تشير إلى:

```text
atoms/قسم 551-600/578_منفذ_التحوط
```

---

## 3. الجذور الموحدة

يسجل Registry الجذور الفعلية الحالية دون نقلها:

```text
forex      → atoms/
crypto     → atoms_crypto/
shared     → shared/
governance  → governance/
```

لا يوجد عدد ثابت داخل تعريف الجذر.

---

## 4. Build Metadata

الـRegistry لا يختار بين المصادر. يسجلها كأدلة:

```text
PACKAGE_BUILD.txt
    QUANT_NQ_FULL_212

config/unified_release.json
    QUANT_NQ_COMPLETE_FULL

575/601 embedded PROJECT_BUILD_ID
    QUANT_NQ_FULL_212
```

الحالة التي ينتجها Registry:

```text
build_contract_status = CONFLICT
build_id = null
```

هذا مقصود: لا يتم استبدال 212 بـ233، ولا اختراع رقم جديد.

---

## 5. Shared

يسجل ملفات `shared/` كمكونات مستقلة في:

```text
snapshot.shared[]
```

ولا تدخل هذه الملفات ضمن `forex` أو `crypto` atom lists.

---

## 6. Governance 901+

لم يتم نقل أو تعديل Atom.

التصنيف يعتمد على حدّ الهوية الموجود في نظام الترقيم: الهوية التي تنتهي بـ901 تُسجّل كـ`governance_control_boundary`.

نتيجة ذلك:

```text
901 موجود في governance[]
901 غير موجود ضمن snapshot.forex[]
```

هذا تصنيف Registry فقط، لا تغيير لهوية الذرة ولا لمسارها.

---

## 7. Execution Target Discovery

الـRegistry يكتشف المكونات ذات قدرات التنفيذ من:

- أحداث `execution.*` المنشورة أو المسموعة.
- `metadata.executable: true`.

لذلك أصبحت 578 قابلة للاكتشاف بالهوية والقدرة، مهما كان عمق الدليل. لا يوجد مسار ثابت لـ578 أو 552 أو 584 أو 708 أو 516 داخل Registry.

---

## 8. Integrity

يسجل Registry:

```text
CORE.lock presence
CORE.lock root_digest
CORE.lock file_count
duplicate atom IDs
discovery failures
```

ولا يكتب ختمًا أو يعيد بناءه.

---

## 9. الاختبارات

أضيفت اختبارات تثبت:

```text

execution lookup
build conflict without guessing
governance separation
empty atom roots
no fixed build count in registry contract
```

الاختبارات لا تغير أي Atom ولا Manifest.
