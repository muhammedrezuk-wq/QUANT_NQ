# توثيق مسار إقلاع النواة واستقلالها

**التاريخ:** 2026-08-27  
**النطاق:** `QUANT_NQ_COMPLETE`  
**نوع العمل:** توثيق أدلة فقط — لا إصلاح، لا ترقيع، لا تغيير إعدادات، لا حذف ملفات.  
**الحكم المطلوب توثيقه:** هل تستطيع النواة الإقلاع دون الذرات؟ وأين يمكن أن يُمنع الوصول إليها؟

---

## 1. الحكم المختصر

ثبت بالتجربة أن مسار Core يستطيع الإقلاع مع مجلد ذرات فارغ:

```text
Core empty atoms: RC=0
```

لذلك لا يجوز تسجيل Finding بصيغة:

```text
Core requires atoms to boot
```

الصياغة الصحيحة هي:

```text
Core boot with zero atoms = مثبت
Unified startup independence from atom/execution prechecks = غير مثبتة
```

النواة نفسها ليست مثبتًا أنها تحتاج ذرّة كي تبدأ. الاشتباه يقع في طبقات التشغيل السابقة للنواة، وفي فحص التنفيذ الموجود داخل مشغّل Core قبل استدعاء `Bootloader.boot()`.

## 2. المسار الفعلي الكامل في الإصدار الحالي

### 2.1 مسار التشغيل الموحّد

```text

        │       │
        │       ├─ scripts/prepare_unified.py       [26-32]
        │       └─ scripts/verify_unified.py        [33-38]
        │
        ├─ spawn run_forex.py                       [86-96]
        │       └─ governance/scripts/run_core.py
        │
        ├─ spawn run_crypto.py                      [97-107]
        │       └─ governance/scripts/run_core.py
        │
        ├─ spawn governance/run_governance.py       [89-105]
        └─ spawn governance/unified_hub.py          [109-115]
```

الملاحظات المثبتة:

- `launch_unified.py:81` يستدعي `prepare()` قبل تشغيل أي Core.
- `prepare():26-38` يوقف المسار إذا فشل إعداد الروابط أو فشل `verify_unified`.
- `verify_unified.py:17-29` يفحص شجرتي الفوركس والكريبتو ويشترط أعدادًا محددة: 233 و76.
- `launch_unified.py:86-107` لا يشغّل Core مباشرة، بل يشغّل غلافي الفوركس والكريبتو.
- هذا المسار ليس مسار Core مستقلًا؛ هو مسار إصدار موحّد له بوابات تغليف قبل الوصول إلى Core.

### 2.2 غلاف الفوركس والكريبتو

#### الفوركس — `scripts/run_forex.py`

- `run_forex.py:8-10`: يضيف جذر المشروع إلى `sys.path`.
- `run_forex.py:11`: يغيّر مجلد العمل إلى `forex_runtime`.
- `run_forex.py:12-16`: يحدد إعداد Core ومسارات التشغيل الخاصة بالفوركس.
- `run_forex.py:18`: يستورد `main` من `governance.scripts.run_core`.
- `run_forex.py:20-21`: يستدعي مشغّل Core عند التنفيذ المباشر.

#### الكريبتو — `scripts/run_crypto.py`

نفس البنية في `run_crypto.py:8-21`، مع:

- إعداد `core_crypto.yaml`.
- جذر ذرات `atoms_crypto`.
- منفذ Core رقم 8020 من ملف الإعداد.

الغلافان لا يحتويان Bootloader خاصًا بهما؛ كلاهما ينتهي إلى `run_core.main()`.

## 3. ما يحدث داخل `run_core.py` قبل Core Boot

### 3.1 نقطة الدخول

`governance/scripts/run_core.py:407-430` هي نقطة الدخول.

ترتيبها الفعلي:

```text
parse arguments                         [407-414]
        ↓
_verify_execution_safety_at_startup()  [415-417]
        ↓
_verify_seal_at_startup()               [418-421]
        ↓
asyncio.run(run(...))                   [422-424]
        ↓
Bootloader.boot() داخل run()            [89-95]
```

### 3.2 فحص سلامة التنفيذ قبل Core Boot

الموضع:

```text
governance/scripts/run_core.py:351-381
```

السلوك:

1. يأخذ `QUANT_ATOMS_ROOT` أو يرجع إلى جذر `atoms` — السطران 360-363.
2. يبحث عن ذرّات التنفيذ باستخدام:

```python
atoms_root.glob("5[57][28]_*")
atoms_root.glob("578_*")
```

السطران 364-365.

3. إذا لم يجدها، يطبع «تُخُطّي» ويرجع نجاحًا — السطران 366-368.
4. إذا وجدها، يستورد `governance.checks.check_execution_safety.inspect` — السطر 370.
5. إذا فشل الفحص يرجع كود 4، وبذلك لا يصل التنفيذ إلى `asyncio.run(run(...))` — السطران 375-381 مع 415-417.

### 3.3 نتيجة التدقيق لهذا الموضع

هذا الفحص موجود **قبل** إنشاء Bootloader وقبل `Bootloader.boot()`.

الموضع لا يثبت أن `core/` نفسها تعرف 578؛ لكنه يثبت أن **مشغّل Core الخارجي** يضع معرفة خاصة بمسار التنفيذ في بوابة تسبق Core Boot.

التصنيف:

```text
F-CORE-002 — Execution Knowledge Inside Core Startup Runner
الحالة: مثبت من ترتيب الاستدعاء والكود.
```

الأثر المعماري المحتمل:

```text
فشل/تعذر فحص execution
        ↓
run_core.main() يرجع قبل asyncio.run(run)
        ↓
لا يصل إلى Bootloader.boot()
```

هذا لا يساوي أن Core تحتاج التنفيذ كي تقلع؛ بل يعني أن الغلاف الذي يشغل Core وضع فحص التنفيذ قبل الإقلاع.

### 3.4 ملاحظة مهمة: الفحص الحالي قد يفوّت 578

شجرة المشروع الحالية تحتوي 578 تحت مجلد قسم:

```text
atoms/قسم 551-600/578_منفذ_التحوط
```

لكن `run_core.py:364-365` يستخدم `glob()` على المستوى المباشر لجذر الذرات، لا بحثًا متكررًا.

النتيجة المرصودة عند التشغيل الحالي:

```text
🛡️ فحص سلامة التنفيذ: تُخُطّي — لا ذرّات تنفيذ في هذه الشجرة إطلاقًا.
```

وهذا لا يعني عدم وجود 578 فعليًا؛ بل يعني أن فحص ما قبل الإقلاع لم يلتقطها في البنية المتداخلة الحالية.

التصنيف المنفصل:

```text
F-CORE-004 — Preflight Scope Does Not Match Recursive Atom Layout
الحالة: مثبت من الكود والمسار الفعلي.
الأثر: احتمال false negative في بوابة فحص التنفيذ.
```

هذا Finding لا يبرر حذف الفحص، ولا تحويل الذرات إلى `auto`؛ هو فقط يوثق عدم تطابق نطاق الفحص مع نطاق الاكتشاف المتكرر.

## 5. مسار Core الداخلي بعد اجتياز البوابات

الموضع:

```text
governance/scripts/run_core.py:38-132
```

الترتيب:

```text
load_core_config()                 [39-43]
        ↓
configure logger                    [44-48]
        ↓
resolve atoms_root                  [50]
        ↓
create Registry/EventBus/services   [54-79]
        ↓
initialize optional secrets         [81-83]
        ↓
create Bootloader                   [89-92]
        ↓
Bootloader.boot()                   [93-95]
        ↓
create HotReloadService             [107-112]
        ↓
start periodic discovery            [109-117]
        ↓
optional API                        [121-132]
        ↓
wait for stop                       [134 onward]
```

### 5.1 اعتماد Bootloader على جذر الذرات

`run_core.py:50` يحدد:

```python
atoms_root = PROJECT_ROOT / core_config.get("atoms_root", "atoms")
```

ثم يمرره إلى `Bootloader` في السطرين 89-92.

هذا اعتماد تشغيلي لا يمنع الإقلاع مع جذر غير موجود؛ لأن `manifest_loader.scan()` في:

```text
core/manifest_loader.py:63-64
```

يرجع:

```python
DiscoveryReport(atoms=[], failures=[])
```

إذا لم يكن الجذر موجودًا.

وفي حالة وجود جذر فارغ، فإن `scan()` يعيد قائمة فارغة، ثم `Bootloader.boot()` يتابع إلى التقرير ويعيد ترتيبًا فارغًا. مواضع ذلك:

- `core/bootloader.py:98-115`: الاكتشاف والفلترة.
- `core/bootloader.py:117-161`: لا توجد حلقة ذرّات فعالة إذا كان `boot_order` فارغًا، ويُعاد التقرير.
- `core/manifest_loader.py:56-64`: البحث لا يوقف Core عند غياب الجذر.

إذن الاعتماد هنا هو **مدخل اكتشاف اختياري**، وليس شرط وجود ذرّة.

### 5.2 Hot Reload بعد الإقلاع

المواضع:

```text
run_core.py:107-117
core/hot_reload_service.py
```

`HotReloadService` لا يُنشأ ولا يبدأ قبل `Bootloader.boot()`؛ يبدأ بعده.

بالتالي:

```text
Core Boot
    ↓
Core initialized
    ↓
Hot Reload / discovery
```

وليس العكس.

## 6. دليل التشغيل الفعلي مع صفر ذرات

الأمر المستخدم:

```bash
QUANT_CORE_CONFIG=<temporary empty-atoms config> \
QUANT_ATOMS_ROOT=<temporary empty-atoms dir> \
python governance/scripts/run_core.py --no-api --demo-seconds 1
```

النتيجة:

```text
🛡️ فحص سلامة التنفيذ: تُخُطّي — لا ذرّات تنفيذ في هذه الشجرة إطلاقًا.
🔒 فحص الختم عند الإقلاع: النواة سليمة ومطابقة.
EMPTY_CORE_RC=0
```

الاختبار كان:

- جذر ذرات فارغًا.
- API معطّلًا.
- مدة تشغيل محدودة ثانية واحدة.
- لا تعديل على ملفات المصدر.
- لا حساب حقيقي، ولا اتصال وسيط، ولا تشغيل تنفيذ.

### حدود هذا الدليل

هذا الدليل يثبت أن مسار `run_core` الحالي **يمر مع جذر فارغ** وأن دورة Core تصل إلى إيقاف نظيف. لكنه لا يثبت أن كل بوابة خارجية أزيلت أو أن `run_core` لا يحتوي أي معرفة تنفيذية؛ بالعكس، يثبت الكود وجود فحص التنفيذ قبل `asyncio.run(run())`.

## 7. مسار الذرات بعد دخول Bootloader

الموضع:

```text
core/bootloader.py:83-161
```

```text
scan atoms_root
    ↓
record manifest failures, without stopping Core
    ↓
filter startup_mode != auto
    ↓
resolve dependencies / cycles / core compatibility
    ↓
instantiate
    ↓
register
    ↓
initialize
    ↓
start
    ↓
BootReport
```

الدليل من الكود:

- `bootloader.py:98`: `scan(self._atoms_root)`.
- `bootloader.py:99-100`: تسجيل فشل المانيفست دون إيقاف Core.
- `bootloader.py:104-114`: `manual` و`lazy` تُستبعدان من التشغيل التلقائي.
- `bootloader.py:115`: حل الاعتماديات.
- `bootloader.py:117-133`: instantiate ثم register.
- `bootloader.py:135-152`: initialize/start لكل المسار القابل للتشغيل.
- `bootloader.py:155-161`: بناء `BootReport`.

### الحكم

```text
startup_mode affects atom lifecycle only.
startup_mode does not logically need to prevent Core Boot.
```

لكن فشل عملية التشغيل الخارجية قبل الوصول إلى `Bootloader.boot()` يظل مسألة مستقلة.

## 9. Findings المعتمدة من هذا التوثيق

### F-CORE-001 — Pre-Core Unified Gates

**الحالة:** مثبت للمسار الموحّد.

```text
launch_unified.py:81
    prepare()
        prepare_unified.py
        verify_unified.py
    ثم spawn للغلافين
```

**الوصف:** الإصدار الموحّد يضع التحضير والتحقق قبل تشغيل أغلفة Core. فشل إحدى هذه الخطوات يمنع الوصول إلى الغلاف أصلًا.

**لا يثبت:** أن Core تحتاج atoms.

**يجب عدم صياغته كـ:** `Core requires atoms to boot`.

### F-CORE-002 — Execution Knowledge Inside Core Startup Runner

**الحالة:** مثبت من `run_core.py:351-381` و`407-424`.

**الوصف:** فحص خاص بمسار التنفيذ يسبق `asyncio.run(run())` الذي ينشئ Bootloader ويستدعي Core Boot.

**الأثر:** فشل الفحص يمكن أن ينهي مشغّل Core قبل الإقلاع.

**المبدأ المتأثر:** فصل Core Boot عن execution-layer validation.

### F-CORE-003 — Core Empty-Atoms Boot Evidence

**الحالة:** مثبت بالتجربة، وهو Evidence مضاد لأي Finding يقول إن Core تحتاج ذرات.

**الدليل:** جذر ذرات فارغ، `--no-api --demo-seconds 1`، رمز عودة 0.

### F-CORE-004 — Preflight Scope Does Not Match Recursive Atom Layout

**الحالة:** مثبت من:

- `run_core.py:364-365` — بحث مباشر فقط.
- وجود 578 تحت `atoms/قسم 551-600/578_منفذ_التحوط`.
- رسالة التشغيل التي أعلنت عدم وجود ذرّات تنفيذ.

**الأثر:** احتمال تجاوز فحص سلامة التنفيذ بسبب عدم اكتشاف الذرة في العمق الصحيح.

### F-CORE-005 — Unified Release Explicitly Disables Full Crypto Auto-Start

**الحالة:** مثبت توثيقيًا من:

```text
config/unified_release.json:8-12
config/unified_layout.json:83+
```

**الوصف:** الإصدار الموحّد يعلن أن المصدر الكامل للكريبتو، والحواس، والقرار، والتنفيذ لا تبدأ تلقائيًا. هذا قرار lifecycle/release، وليس شرطًا من شروط Core Boot.

## 10. ما لم يُحسم بهذا التوثيق

هذا الملف لا يحكم على:

- سلامة 576 أو 578 أو 580 أو 901 من ناحية منطق التداول.
- صلاحية جعل أي ذرّة `auto`.
- صحة كل مسارات Windows Service أو Task Scheduler.
- نجاح `launch_unified.py` في بيئة Windows فعلية مع الصلاحيات والـvenv.
- توافق الوثائق القديمة التي تشير إلى Core V1.6 مع Core الحالية V1.24.
- استقلال `core/` عن كل الوحدات الخارجية في عملية التغليف؛ هذا يحتاج تدقيق import boundary منفصلًا.

## 11. قرار الإيقاف قبل الإصلاح

حتى اكتمال خريطة الاعتماديات، لا يتم:

- تعديل `startup_mode`.
- إزالة فحص execution safety.
- نقل 578 أو إعادة ترقيمها.
- تعديل `CORE.lock`.
- بناء Supervisor أو تسجيل خدمة تشغيل تلقائي.
- حذف النسخة القديمة.
- ربط حساب حقيقي.

**النتيجة النهائية لهذا الملف:**

```text
Core can boot with zero atoms: PROVEN.
The outer unified/preflight path is not independent from atom/execution checks: PROVEN/CONTRADICTED by current flow.
No code was changed by this documentation step.
```
