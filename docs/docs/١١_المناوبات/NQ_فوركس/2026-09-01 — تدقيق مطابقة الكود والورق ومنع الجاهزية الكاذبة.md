بلا مخالفة مانيفست. لكن الشجرة **ليست إصدارًا أخضر كاملًا**:

- تشغيل كريبتو الحي لم يكن متاحًا وقت الفحص.

إخراج `verify_unified.py = READY` صحيح فقط ضمن ما تقيسه الأداة: الاكتشاف
وختم Core وبعض عقود الإصدار. لا يغطي الاختبارات والبناء والشيكسَم والخزنة

## 3. تفصيل إخفاقات المستودع

إخفاقا end-to-end ليسا عطل شبكة كما قالت الورقة السابقة. الـfixture في
`tests/core/test_end_to_end.py` يبني مشروعًا مؤقتًا وينسخ:

```text
core scripts governance transport security build_registry
```

لكنه لا ينسخ `clock/`. لذلك يخرج `scripts/run_core.py` بسبب الوحدة المفقودة
قبل أن يصبح HTTP قابلًا للوصول.

الإخفاق الثالث حقيقي في الحالة الحالية: الذرّة 007 تقارن المصدر بخط أساس فيه
`9` بصمات متقادمة.

## 4. تفصيل إخفاقات كريبتو

### 1001

ثلاثة اختبارات تطلب وسيطًا باسم `tmp_dir`. مشغل الملف اليدوي يستدعي الدوال
ويمرر المسار بنفسه، لكن pytest لا يجد fixture بهذا الاسم. النتيجة `3 errors`.

### 2103

المنفذ الحالي يخزن مفاتيح `_candles` متضمنة `period_start`، مثل:

```text
('A', 'BR', 'NQ', 60.0)
```

واختباران ما زالا يتوقعان مفتاحًا ثلاثيًا. النتيجة `6 passed, 2 failed`.
هذه فجوة عقد/اختبار تحتاج حكمًا، ولا تُحل بإخفاء الفشل.

### 2719

الجامع يركب handlers على `asmar.core` وعلى root logger، بينما
`core/logger.py` يكتب إلى `quant_nq.core` ويضبط `propagate=False`. لذلك لا
تصل سجلات Core إلى الجامع. النتيجة `1 passed, 4 failed`.

### عيب الأداة

`619` موجودان داخل شجرة الأقسام.

## 6. الواجهة والتهيئة

بناء الجذر غائب. يوجد بناء متطابق تحت runtime فوركس وكريبتو قبل التهيئة، لكن
`prepare_unified.py` يستبدل governance داخل runtime برابط إلى جذر governance.
بعد ذلك يعود الجميع إلى البناء المفقود. `setup_machine.py` يتحقق من البناء
ولا يبنيه، وworkflow الكامل لا يبنيه قبل فحص المشروع.

إذًا عبارة «clone نظيف ثم زر التهيئة ينجح» غير مثبتة بل يناقضها فحص البنية.

## 7. نقاط الإطلاق

تمت قراءة الأزرار كل واحد على حدة:

- زر فوركس → `launch_market.py --market forex` → `8010/8092/8090`.
- زر كريبتو → `launch_market.py --market crypto` → `8020/8093/8091`.
- `START_LOCAL.bat` → `launch_market.py --both` → لوحتان منفصلتان.
- «غرفة القيادة» → `governance/app.py` → خادمان مباشران على `8090/8091`
  ونافذتا WebView.
- `launch_unified.py` → hub واحد على `8090` وخلفيتان على `8092/8093`.

لا توجد معمارية إطلاق واحدة في المصدر؛ يجب تسمية نقطة الدخول في كل ورقة.

## 8. كريبتو: الخريطة والتشغيل اليدوي

الاكتشاف يجد `80` مانيفستًا: `33 auto` و`47 manual`.
`unified_layout.json` يعلن `74` full IDs، لكن `5` منها غير موجودة، وفي المقابل
توجد `9` ذرّات غير ممثلة في الخريطة. الموجود فعليًا من full source هو `69`:
منها `22 auto` و`47 manual`. مفتاح `excluded_from_auto_start` لا يقرأه أي كود
تشغيل؛ الحكم الفعلي من `startup_mode` في المانيفست. لذلك
`config/unified_release.json` القديم الذي يقول `full_source_auto_start=false`
لا يصف التنفيذ الحالي، كما لا تصفه أرقامه `1.27.0/77`.

الذرّات `2702`, `2707`, `2720` يدوية فعلًا ولم تُفعّل. لم يُنفذ قرار فصل
الإطلاق ولا قرار تشغيل التخزين.

## 10. الأمن

الفحص وجد طبقة الأمن موجودة ومفعلة و`allow_prompt=False`، لكنه وجد:

```text
vault_present=False
key_count=0
SECURITY_STATE=NOT_CONFIGURED
```

مسح محدود لتواقيع مفاتيح خاصة وتوكنات شائعة لم يجد تطابقًا. هذا ليس pentest،
ولا يثبت المصادقة أو الربط الشبكي حيًا.

## 13. ما بقي

1. حسم أعطال الاختبارات بدل إعلان الأخضر.
2. بناء واجهة الجذر أو تغيير عقد النشر.
3. إصلاح أداة baseline وتجديد الخطوط بعد مراجعة.
4. توليد شيكسَم للحزمة الفعلية.
5. توحيد معمارية الإطلاق ومسار بيانات كريبتو أو توثيق قرار صريح.
6. تهيئة الخزنة وإجراء فحص حي على Windows مع الخدمات والبيانات الخارجية.
7. توفير ZIP السابقة إن أريد إثبات الانحدار بايتًا ببايت.

**لا ينفذ أي بند برمجي مما سبق دون ختم `NQ`.**

  `governance/ui/built/index.html` ضمن الفحوص الخمسة التي شغّلها.

  Python أو إعداد أو اختبار أو مانيفست عُدّل.
