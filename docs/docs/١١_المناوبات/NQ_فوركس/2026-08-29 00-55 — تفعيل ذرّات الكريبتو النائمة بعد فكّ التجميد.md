## ١) التشخيص — لماذا كانت الأحداث «بلا ناشر»

تقرير المالك أظهر 60+ حدثًا «محدا بينشره وبيستنّاه». **القياس كشف السبب:**

```
84 منيفست كريبتو بالقرص  ·  33 شغّالة فقط  ·  51 نائمة
وكلّها بالضبط: startup_mode = manual
```

**فالأحداث لم تكن مقطوعة — ناشروها موجودون لكن نائمون.**

### ولماذا فشل التشغيل عبر الـAPI أوّلًا
`POST /gov/atoms/{id}/start` أعاد **404 لكل الـ51**. السبب بالكود
(`core/bootloader.py:106-111`): الذرّة بـ`startup_mode != auto`
**تُحذف من `working` كليًّا** فلا تُسجَّل أصلًا — والتعليق في الكود يقول
«يبقى تشغيلها اليدوي متاحًا عبر API» وهو **غير صحيح عمليًّا**.
⇒ التفعيل يتطلّب تعديل المنيفست، لا نداء API.

## ٢) ما نُفِّذ

**أ) تفعيل 51 منيفستًا** — سطر واحد لكلٍّ: `startup_mode: manual → auto`.
- **نسخة احتياطيّة كاملة قبل أي تعديل** →
  `Desktop\نسخة منيفستات الكريبتو قبل التفعيل 2026-08-29`
- **فُحصت كل ذرّة قبل التشغيل:** صفر منها تنشر حدث تنفيذ/أمر
  (`execution.*` · `order.*` · `trading.final` · `halt` · `brain_signal`).
  كلّها بنية تحتيّة: تغذية · مخازن · قياس · سلامة.

**ب) 🔑 إصلاح تبعيّة عابرة للأسواق — الأهمّ**

بعد التفعيل بقيت ذرّتان مستبعَدتين:
```
#2003 الساعة (كريبتو)  →  dependencies: id 608   ← ذرّة فوركس!
#2111 جسر الوقت        →  dependencies: id 2003  ← سقطت بالتتابع
```
**و#608 موجودة في الفوركس فقط** (`atoms/قسم 601-650/608_مزامنة_الوقت`)،
ولا #608 ولا #2608 في الكريبتو ⇒ استُبعدت #2003 فسقط معها جسر الوقت.

**هذا خلط أسواق صريح داخل المنيفست** — وهو ما نهى عنه المالك حرفيًّا:
> «ما بصير يخلط بين فوركس وكريبتو»

**الحلّ بلا خلط:** نُقل نظير كريبتوّي مستقلّ
```
atoms_crypto/قسم 2601-2650/2608_مزامنة_الوقت/     (منقول عن #608)
   id: 608 → 2608   ·   dependencies: []  (لا تبعيّة على شيء)
   ينشر: time.ntp.samples.state · time.ntp.drift · time.utc.stale
ثمّ #2003:  dependencies id 608 → 2608
```

**النتيجة المقاسة:**
```
#2003 الساعة      🟢 quality=SYNCED  (انحراف 0.400 ثانية)
#2111 جسر الوقت   🟢
#2608 مزامنة الوقت 🟢
```
**والاعتماد صار داخل الكريبتو بالكامل — صفر تبعيّة على الفوركس.**
