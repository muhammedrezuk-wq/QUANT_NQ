## ٢. السبب الجذريّ — عطبان، وكلاهما قفلٌ دائم

### أ) قفل بينج-بونغ على زوج الأوزان — `166/atom.py:136`

كان يعيد توازن الوزن المقابل عبر `apply_command` **بلا تمرير `confirm`**.
و`shared/decision_dials.py:280` صريح: بلا `confirm` = مسودّة `UNAPPROVED`.

```
اعتماد ANALYSIS_SLOW_WEIGHT=47  →  FAST=53 يرتدّ مسودّة غير معتمدة
اعتماد ANALYSIS_FAST_WEIGHT=53  →  SLOW=47 يرتدّ مسودّة غير معتمدة
```

**لا يجتمع الاثنان معتمدَين أبدًا.** والأثر مقيس في السجلّ:
`ANALYSIS_FAST_WEIGHT · source=OWNER · status=UNAPPROVED` — اعتُمد ثمّ أُعيد.

### ب) أربعة عيارات بلا مستلِم — الذرّة ٤١١

`DIALS` تُعلن أنّ مالك هذه الأربعة هو ٤١١:

```
NEWS_HIGH_WINDOW_BEFORE_MIN · NEWS_HIGH_WINDOW_AFTER_MIN
NEWS_MEDIUM_WINDOW_MIN      · NEWS_LIGHT_WINDOW_MIN
```

والذرّة ٤١١ **لم تكن تشترك بـ`decision.settings.command` ولا تنادي `apply_command` قطّ**.
فكل أمر اعتماد لها يسقط بلا مستلِم ⇒ `source=UNSET` أبدًا.
واثنان منها (`medium`/`light`) يعلنان مفتاحَي إعداد **لم يكونا في إعداد ٤١١ أصلًا**.

### الرابط الذي جعل عطب الأخبار يقفل التداول

`ParameterRegistry.unapproved()` (`shared/parameter_registry.py:169`) **لا يسأل عن صاحب المُعامِل**:

```sql
SELECT name FROM parameters WHERE status != 'APPROVED'
```

⇒ مُعامِلٌ واحد غير معتمَد يُبقي **كل** بطاقة قسم `provisional` بسبب `UNAPPROVED_PARAMETER`.

**أربعة عيارات أخبار يتيمة أقفلت سلسلة القرار كلّها.**
