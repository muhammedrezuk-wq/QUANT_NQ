# أمر مالك — اعتماد مسار إغلاق الإصدار

**التاريخ:** 2026-09-01  
**الحالة:** العقود والواجهة والفحص أُنجزت؛ التشغيل الحي على Windows والخزنة ما زالا مطلوبين.  
**النص الحاكم:** «العقد والقرارات → الواجهة → الفحص → التشغيل الحي → التحقق → الشيكسم → الالتزام → حزمة التسليم».

---

## 1. القرارات النافذة

بختم المالك: **«NQ — نفّذ واترك التخزين يدويًا»**:

1. الإطلاق الرسمي زران مستقلان: فوركس وكريبتو، كلاهما عبر `launch_market.py`.
2. جذر بيانات كريبتو الوحيد `crypto_runtime/var`؛ لا قراءة أو كتابة فعالة في
   `ROOT/var/crypto` ولا نسخ مزدوجة ولا مزامنة.
3. `manifest.startup_mode` هو سلطة الإقلاع الوحيدة: `33 auto / 47 manual`.
4. أزيل العقد الميت `excluded_from_auto_start`، ولم تُنشأ allowlist بديلة.
5. الذرّات `2702` و`2707` و`2720` بقيت `manual`.
6. اعتمد المالك الاحتفاظ بخطوط السلامة وتجديدها للكود المختوم؛ هذا القرار لا
   يشمل `SHA256SUMS.txt`.

## 2. حالة مسار الإغلاق

| المرحلة | الحالة المقاسة |
|---:|---|
| العقود والقرارات | مكتملة في الإعداد والكود والورق ومرايا runtime |
| بناء الواجهة | مكتمل محليًا: `governance/ui/built/index.html` |
| CI | يبني الواجهة بـNode 22 و`npm ci && npm run build` قبل `check_project.py` |
| فحص المشروع | ناجح |
| التشغيل الحي | ينتظر جهاز Windows والخزنة والوسطاء |
| التحقق النهائي | ساكن ناجح؛ الحي ينتظر Windows |
| `SHA256SUMS.txt` | لم يُجدّد، كما أمر المالك |
| الالتزام وZIP | لم يُنفذا |

## 3. التنفيذ المثبت

- صُحح `config/unified_release.json` ومراياه إلى Core `1.31.0`، فوركس `233`،
  كريبتو `80`، `33/47`، الإطلاق المنفصل، وجذر البيانات الرسمي.
- صُحح `unified_layout.json`: خريطة المصدر الفعلية `69`، الذرّات الإضافية
  التسع معلنة، والعقد الميت محذوف.
- وُجهت اللقطات والجورنال وقواعد التحليل والأخبار والجسر ومفاتيح MEXC
  وعضوية الكون إلى `crypto_runtime/var`؛ صارت إعدادات Core النسبية
  `var/snapshots` و`var/journal.jsonl` بلا طبقة `var/crypto`.
- صارت تعليمات التهيئة والبدء توجه إلى زري السوق؛ الأدوات المجمعة وُسمت
  داخلية/قديمة وليست العقد الرسمي.
- أضيف `tests/test_release_contract.py`، وصُحح اختبار عقد الإطلاق الساكن.
- بُنيت الواجهة دون ثغرات npm (`0 vulnerabilities`). تحذير Vite الوحيد حجم
  chunk مقداره نحو `1.34 MB`؛ لم يُخفَ ولم يُحوّل إلى مانع بلا قياس حي.

## 4. قرار التحذيرات

### الإسقاط الصامت 870

كان التحذير حقيقيًا من جهة الرؤية: حالات `experiment.state` غير المقبولة كانت
ترجع بلا عداد. رُفع الإصدار `1.0.0 → 1.0.1` دون تغيير قرار المعايرة، وأضيف:

- `ignored_status` للحالات غير الموجهة لموافقة الظل.
- `invalid` للحمولات المشوهة/الناقصة.
- ظهور العدّادين في الصحة والنشر واللقطة، واختبار انحدار لهما.

اختفى التحذير؛ بقيت نتيجة المدقق `0` مخالفات و`20` تحذيرًا.

### استثناءات الحجم الثلاثة

`166` و`454` و`622` تبقى مستثناة بالأسباب المسجلة داخل المدقق. لم يُضغط
منطقها ولم يُخف التحذير.

### الحلقات الخلفية الـ17

| الذرّات | التصنيف والقرار |
|---|---|
| `517`, `586` | حارسا مهل أمان؛ يجب أن تنتهي المهلة حتى إن انقطع نبض السوق. إبقاؤهما مع بقاء التحذير. |
| `701`, `703`, `704`, `712`, `713`, `718` | تفريغ مخازن مؤقتة لضمان الكتابة عند انخفاض الأحداث. حلقات محدودة وتُلغى عند الإيقاف؛ إبقاء التحذير والمراقبة الحية. |
| `601` | نبض جسر MetaTrader وهوية الحساب؛ تكامل خارجي دوري. إبقاؤه مع المراقبة. |
| `608` | مزامنة NTP ومصدر وقت؛ بوابة خارجية دورية. إبقاؤها مع المراقبة. |
| `609`, `611`, `618`, `619` | قارئات/مضخة جسر MetaTrader والحساب؛ polling خارجي مع إلغاء عند الإيقاف. إبقاء التحذير حتى القياس الحي. |
| `616`, `620` | مهمتان محدودتان تُطلقان من النبض وتمنع رايات busy التوازي؛ ليستا حلقتين دائمتين، لكن التحذير بقي ظاهرًا. |

كل الملفات الـ17 تملك مسار `stop` ونداء `cancel()`، لكن `11` منها لا تنتظر
المهمة بعد الإلغاء؛ لذلك لم تُمنح إعفاءات في المدقق ولم تُخف التحذيرات. الحكم:
ليست مانع مصدر بعد الاختبارات، وتبقى بند مراقبة في تشغيل Windows الحي.

- لا تجديد لـ`SHA256SUMS.txt` قبل اكتمال التشغيل الحي والتغييرات.

## 7. إغلاق فجوة نتائج كريبتو اليدوية — ختم `nq`

بعد القياس تبيّن أن `2275` كانت تستمع `platform.trade_event` بلا أي ناشر
كريبتو، لذلك كان عدّادا الخسارة اليومية والخسائر المتتالية يبقيان صفرًا في
التشغيل الفعلي. اختار المالك **الإدخال اليدوي من لوحة كريبتو** ومنح ختم تنفيذ
جديدًا: **`nq`**.

نُفذ العقد الآتي:

1. أضيفت بطاقة «تسجيل نتيجة صفقة مغلقة» إلى `Mexc.tsx`: معرّف صفقة MEXC
   فريد، رمز، وPnL رقمي صافي بعد الرسوم، مع سجل آخر النتائج.
2. `POST /gov/mexc/trade-result` يعمل في سوق كريبتو فقط. الطلب الأول لا ينشر
   شيئًا بل يصدر ملخصًا ورمز تأكيد صالحًا 60 ثانية؛ النشر لا يحدث إلا بالطلب
   الثاني المطابق وبعد حوار التأكيد النهائي في الواجهة.
3. التحقق الخادمي مغلق الحقول: صيغة المعرّف والرمز، وPnL رقمي منتهٍ مع رفض
   `bool`، وطول اسم المسجّل والملاحظة. أي تغيير لبيانات retry تحت
   المعرّف نفسه مرفوض.
4. سجل SQLite متين في
   `crypto_runtime/var/governance/manual_trade_results.db` يحفظ البيانات وحالة
   التسليم وعدد المحاولات. المعرّف مفتاح فريد؛ `DELIVERED` لا يُنشر ثانية.
   التسليم غير المؤكد يبقى ظاهرًا ويعاد **بنفس المعرّف ونفس الحمولة** فقط.
5. يسمح محوّل كريبتو الخارجي وحده بـ`platform.trade_event`؛ محوّل فوركس يرفضه،
   وCore المختومة لم تُعدّل ولم تُضمّن مفردات السوق.
6. رُفعت `2275` إلى `1.6.1`: تشترط `trade_id` وPnL منتهيًا، تحفظ آخر 2000
   معرّف في اللقطة، وتتجاهل المكرر. الربح يصفر سلسلة الخسائر، الخسارة تزيدها،
   والتعادل لا يُعد خسارة. الصحة تعرض PnL والسلسلة وعدد النتائج والمكرر/المرفوض.
7. صار `check_events.py` يقيس هذه الحافة صراحةً بدل أن يكتفي بسجل فوركس:
   لوحة MEXC → ناشر الحوكمة الموثق → `platform.trade_event` → المستمعون
   `[2275, 2702, 2704, 2707, 2720]`، مع إثبات بقاء فوركس مغلقًا.

**حد الادعاء:** بلوغ `daily_loss_halt_pct=2%` أو
`max_consecutive_losses=3` يجعل `2275` تنشر `DAILY_RISK_HALTED` وترفض
**التوصيات الجديدة**. هذا لا يمنع إنسانًا من وضع أمر مباشر في حساب MEXC ولا
يوصف بقاطع وسيط.

لم تُفعّل الذرة `2901`، ولم تتغير سلطة الإقلاع أو الأعداد
`33 auto / 47 manual`، وبقيت `2702/2707/2720` يدوية. لم يُجدّد
`SHA256SUMS.txt`، ولم يحدث commit أو ZIP.

- اختبارات العقود المتأثرة: `33 passed`.
- سلة المستودع النهائية: `896 passed, 1 skipped`؛ سلة كريبتو: `237 passed`.
- `verify_unified.py`: `READY`، Core `1.31.0`، فوركس `233`، كريبتو `80`،
  والختم سليم. `check_versions.py`: `233` مفحوصة و`0` اختلاف.
- جُددت خطوط السلامة المأذونة ثم اجتاز `--check`: root `1300`، Forex

غير مثبتين. أي رقم أقدم أعلاه هو قياس ما قبل هذا الإصلاح.
