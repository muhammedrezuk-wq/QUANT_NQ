# تدقيق حدود إقلاع النواة — الجولة الثانية

**التاريخ:** 2026-08-27  
**النطاق:** حدود `Core Boot` فقط  
**نوع العمل:** تدقيق إثباتي بلا إصلاح.  
**المرجع السابق:** `التدقيق/٢٣ مسار إقلاع النواة واستقلالها.md`

---

## 1. قاعدة التدقيق

السؤال الوحيد في هذه الجولة:

> هل يمكن لطبقة Core أن تصل إلى `Bootloader.boot()` وتبقى قيد التشغيل دون الاعتماد على وجود أو صحة أي ذرة؟

لا تدخل هذه الجولة في إصلاح 576 أو 578 أو 580 أو 901، ولا في تغيير `startup_mode`، ولا في إنشاء Supervisor.

---

## 2. النتيجة المؤكدة

تم تشغيل مشغّل Core مع:

- مجلد atoms فارغ.
- API معطّل (`--no-api`).
- مدة اختبار محدودة (`--demo-seconds 1`).
- فحص الختم سليم.
- لا تشغيل وسيط ولا حساب حقيقي.

النتيجة:

```text
🛡️ فحص سلامة التنفيذ: تُخُطّي — لا ذرّات تنفيذ في هذه الشجرة إطلاقًا.
🔒 فحص الختم عند الإقلاع: النواة سليمة ومطابقة.
EMPTY_CORE_RC=0
```

### الحكم

```text
F-CORE-003 — Core Boot With Zero Atoms
الحالة: مثبت بالتجربة.
```

هذا الدليل يمنع صياغة أي نتيجة تقول إن Core تحتاج atoms لكي تقلع.

### قيد الدليل

الاختبار مرّ عبر بوابتي `execution safety` و`seal` الموجودتين في `run_core.py` قبل `asyncio.run(run())`. لذلك يثبت قدرة المسار الحالي على المرور عند غياب الذرات، لكنه لا يثبت أن كل بوابات ما قبل Core مستقلة معماريًا عن الذرات. هذه الاستقلالية موضوع Findings منفصلة أدناه.

## 4. نتائج فحص كل طبقة

### 4.1 `launch_unified.py`

الأدلة:

- `scripts/launch_unified.py:26-38`: `prepare()` يشغّل `prepare_unified.py` ثم `verify_unified.py`، ويوقف المسار عند أي رمز رجوع غير صفري.
- `scripts/launch_unified.py:81`: استدعاء `prepare()` يسبق تشغيل أي عملية Core.
- `scripts/launch_unified.py:86-107`: تشغيل أغلفة الفوركس والكريبتو عبر `spawn`.
- `scripts/launch_unified.py:117-129`: انتظار المنافذ وإرجاع كود فشل إذا لم تصبح كل المنافذ جاهزة.

الحكم:

```text
F-CORE-001 — Unified Pre-Core Gates
الحالة: مثبت للمسار الموحّد.
```

هذا Finding يصف اعتماد **مسار الإصدار الموحّد** على بوابات تغليف قبل تشغيل Core، ولا يصف Core نفسها بأنها تحتاج atoms.

### 4.2 `verify_unified.py`

الأدلة:

- `scripts/verify_unified.py:17-22`: مسح `atoms` و`atoms_crypto`.
- `scripts/verify_unified.py:23-29`: اشتراط 233 ذرة فوركس و76 ذرة كريبتو ووجود 1001 و1002.
- `scripts/verify_unified.py:60-65`: فحص ختم Core جزء من التحقق الموحّد.
- `scripts/verify_unified.py:72-77`: أي فشل يعيد كود 1.

الحكم:

هذه البوابة **إصدار/تغليف** وليست جزءًا من `Bootloader`. فشلها يمنع تشغيل المسار الموحّد، لا يثبت فشل Core Boot.

### 4.3 `run_core.py` — فحص التنفيذ

الأدلة:

- `run_core.py:351-381`: تعريف بوابة execution safety.
- `run_core.py:364-365`: البحث عن ذرّات التنفيذ باستخدام `glob` مباشر.
- `run_core.py:366-368`: عند عدم العثور على الذرات يعلن الفحص التجاوز ويرجع نجاحًا.
- `run_core.py:370-381`: عند العثور عليها يستدعي `check_execution_safety.inspect()` وقد يرجع كود 4.
- `run_core.py:415-417`: هذه النتيجة تُفحص قبل `asyncio.run(run())`.

الحكم:

```text
F-CORE-002 — Execution Knowledge Before Core Boot
الحالة: مثبت من ترتيب الاستدعاء.
```

فحص التنفيذ ليس داخل `core/`، لكنه داخل مشغّل Core وقبل بدء دالة `run()` التي تنشئ Bootloader. لذلك حدّ المسؤولية بين Core Boot وExecution Preflight غير منفصل حاليًا في نقطة الدخول.

### 4.4 `run_core.py` — فحص النطاق غير المتكرر

الأدلة:

```text
run_core.py:364-365
atoms_root.glob("5[57][28]_*")
atoms_root.glob("578_*")
```

المسار الفعلي:

```text
atoms/قسم 551-600/578_منفذ_التحوط
```

النتيجة التشغيلية المرصودة:

```text
فحص سلامة التنفيذ: تُخُطّي — لا ذرّات تنفيذ في هذه الشجرة إطلاقًا.
```

بينما `core/manifest_loader.py:56-77` يستخدم بحثًا متكررًا (`rglob`/`os.walk`) ويجد 578.

الحكم:

```text
F-CORE-004 — Preflight Scope Does Not Match Recursive Atom Layout
الحالة: مثبت.
```

الأثر المحتمل: false negative في الفحص القبلي. هذا لا يبرر إزالة الفحص ولا تغيير `startup_mode`.

### 4.5 `run_core.py` — فحص ختم Core

الأدلة:

- `run_core.py:384-404`: تعريف فحص الختم.
- `run_core.py:418-421`: وضعه قبل `asyncio.run(run())`.
- النتيجة المرصودة: `النواة سليمة ومطابقة`.

الحكم:

فحص الختم متعلق بملفات Core نفسها، ولا توجد في هذه الجولة قرينة تجعله اعتمادًا على atoms أو execution. يبقى بوابة سلامة خارجية قبل Core، لكنه مختلف جوهريًا عن فحص 578.

## 5. حدود `atoms_root` والبيئة

### ما يقرأه الإقلاع الفعلي

`run_core.py:39-43` يقرأ `QUANT_CORE_CONFIG`، ثم `run_core.py:50` يحدد:

```python
atoms_root = PROJECT_ROOT / core_config.get("atoms_root", "atoms")
```

هذا هو المسار الذي يمر إلى:

```text
run_core.py:89-92 → Bootloader(..., atoms_root, ...)
```

### ما يقرأه فحص execution

`run_core.py:360-363` يقرأ `QUANT_ATOMS_ROOT`، ثم يبحث داخله.

### النتيجة

يوجد مصدران لمسار الذرات:

```text
Bootloader       ← core_config.atoms_root
execution check  ← QUANT_ATOMS_ROOT
```

في الغلافين الحاليين القيمتان مضبوطان عمليًا لنفس الجذر:

- `scripts/run_forex.py:12-13`.
- `scripts/run_crypto.py:12-13`.

لكن لا يوجد في `run_core.py` تحقق صريح من أن المصدرين متساويان.

### تصنيف إضافي

```text
F-CORE-006 — Dual Atom-Root Sources at Runner Boundary
الحالة: مثبت بنيويًا؛ الأثر الفعلي يحتاج تجربة تغيير متعمد للمسارين.
```

لا يُسجل هذا كفشل Core Boot بعد؛ هو خطر انجراف إعداد بين الفحص والمسار الفعلي.

## 6. API اختيارية لكن مفعّلة افتراضيًا

الأدلة:

- `config/core.yaml:21-24`: `enable_api: true`.
- `run_core.py:121-129`: إذا كانت API مفعّلة يستدعي `_start_api()`.
- `run_core.py:284`: الاستيراد داخل `_start_api` يبدأ بـ`import uvicorn`.
- `core/api/app.py:26`: استيراد FastAPI عند تحميل الوحدة.
- `pyproject.toml`: FastAPI وUvicorn تحت optional extra اسمه `api`، وليسا ضمن dependencies الأساسية.
- `requirements.txt`: يحتويهما، لكن هذا يعتمد على أن المستخدم شغّل تثبيت المتطلبات الكامل.

الاختبار الفعلي لطبقة Core الفارغة استعمل `--no-api`، لذلك لا يثبت نجاح API في بيئة لا تحتوي الاعتماديات الاختيارية.

### تصنيف

```text
F-CORE-007 — Default API Path Depends on Optional Installation
الحالة: مثبت بنيويًا؛ لم يُسجل كفشل Core Empty Boot.
```

الأثر: قد تقلع Core داخليًا ثم ينتهي مشغلها عند محاولة إنشاء API إذا كانت الاعتماديات غير مثبتة. هذا فشل تشغيل/توزيع، وليس دليلًا على اعتماد Core على atoms.

## 7. Hot Reload بعد Core وليس قبله

الأدلة:

- `run_core.py:89-95`: إنشاء Bootloader ثم استدعاء `boot()`.
- `run_core.py:107-117`: إنشاء `HotReloadService` وتشغيل الفحص الدوري بعد تقرير الإقلاع.
- `core/hot_reload_service.py:111-141`: بدء الحلقة الدورية ونقطة الفحص الوحيدة.
- `core/hot_reload_service.py:148-160`: البصمة والمسح المتكرر ينفذان بعد تشغيل الخدمة.

الحكم:

```text
Core Boot
    ↓
Bootloader report
    ↓
HotReloadService
```

التحميل الحار ليس سببًا لإقلاع Core، ولا يمكنه إنقاذ مسار لم يصل أصلًا إلى Core.

داخل Hot Reload نفسه، `core/hot_reload_service.py:190-196` يطبق `startup_mode` على الذرات الجديدة. هذا صحيح كمبدأ lifecycle للذرة، ولا يحول `manual` إلى شرط لإقلاع Core.

## 8. حالة الاختبارات في بيئة التدقيق

تم تشغيل:

```bash
pytest -q tests/core
```

فحدث خطأ تجميع مباشر:

```text
ModuleNotFoundError: No module named 'fastapi'
```

في محاولة استبعاد اختبار WebSocket، تم تشغيل اختبارات Core بدون ذلك الملف، لكن البيئة لم تحتوي `pytest-asyncio`، فظهرت أخطاء:

```text
async def functions are not natively supported
Unknown pytest.mark.asyncio
```

النتيجة المسجلة:

```text
62 failed, 64 passed, 61 warnings
```

لكن هذه النتيجة **غير صالحة للحكم على منطق Core** لأن الاعتماديات اللازمة للاختبارات غير مثبتة في بيئة التدقيق. تُسجل كالتالي:

```text
F-CORE-008 — Core Test Environment Is Not Provisioned
الحالة: مثبت كفجوة قابلية إعادة إنتاج، لا كفشل كود.
```

لا يجوز تحويل رقم 62 إلى «62 عطلًا في النواة».

## 9. مصفوفة الحكم النهائية

| البند | الحكم |
|---|---|
| Core تقلع مع مجلد ذرات فارغ | مثبت بالتجربة |
| Core تحتاج 578 كي تقلع | غير صحيح / مرفوض |
| `manual` يمنع Core Boot | غير مثبت / غير صحيح معماريًا |
| `launch_unified` يضع بوابات قبل تشغيل الأغلفة | مثبت |
| `run_core` يضع execution safety قبل `asyncio.run(run())` | مثبت |
| فحص execution يطابق عمق اكتشاف الذرات | غير صحيح؛ false negative محتمل |
| Hot Reload يبدأ قبل Core | غير صحيح؛ يبدأ بعد Bootloader |
| نجاح API الافتراضية في بيئة بلا optional deps | غير مثبت |
| اختبارات Core قابلة للحكم في البيئة الحالية | غير صحيح؛ البيئة ناقصة |
| ضرورة تحويل كل الذرات إلى auto | غير مبررة |

## 11. ما لم يُفعل

في هذه الجولة لم يتم:

- تعديل `core/`.
- تعديل `run_core.py`.
- تعديل `launch_unified.py`.
- تعديل `startup_mode`.
- تعديل 578 أو أي ذرة.
- تعديل `CORE.lock`.
- حذف أو نقل ملفات.
- إنشاء Supervisor.
- تشغيل حساب أو وسيط.

**الخلاصة:**

```text
Core zero-atom boot = PROVEN.
The current outer/runner boundary is not architecturally independent
from execution and release preflights = PROVEN.
The next action is a boundary decision, not an atom patch.
```
