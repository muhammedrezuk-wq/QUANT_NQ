## ١) العطل

ذرّتان كهرمانيّتان بشكل دائم:
```
#619 Account State Reader : ACCOUNT_STATE_STALE
#717 Trading Data Integrity: ROWS_IN_THE_FUTURE
```

`CLOCK_NOT_SYNCED` ثمّ `ACCOUNT_STATE_STALE`) — **وكلّها من جذر واحد.**

## ٢) السبب الجذريّ — مؤكَّد بالكود والقياس المباشر

**قياس مباشر من محطّة MT5 (لا من قاعدة وسيطة):**
```
tick.time (خادم الوسيط) − الوقت الحقيقيّ = 10,799.77 ثانية = 3 ساعات بالضبط
```

**الدليل في الكود — `mt5/QUANT_NQ.mq5` سطر 775-776:**
```cpp
"UPDATE account_v2 SET updated_at=%d WHERE account_id='%s';", (int)TimeGMT(), ...
```
`TimeGMT()` في MQL5 تُحسب من **ساعة خادم الوسيط ومنطقته الزمنيّة**، لا من ساعة
الويندوز. لذلك تصحيح NTP للجهاز **لا يؤثّر إطلاقًا** — العلاقة مقطوعة بالتصميم.

**ما نُفي بالقياس (مهمّ — لا تُعِد فحصه):**
- ❌ ساعة الويندوز: سليمة — `w32tm` أعطى **103 ملّي ثانية** (فحصها المالك بنفسه)
- ❌ ذرّة #608 (مزامنة NTP): سليمة — انحراف 0.12 ثانية عبر 3 خوادم عالميّة
- ❌ ذرّة #3 (الساعة الرسميّة): `SYNCED`
- ❌ «خادم متلاعب»: **ليس تلاعبًا** — فرق منطقة زمنيّة ثابت (3×3600 بالضبط)
