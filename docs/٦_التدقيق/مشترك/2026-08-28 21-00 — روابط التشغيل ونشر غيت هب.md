## المشكلة الأولى — النظام لا يقلع بعد فكّ ضغط جديد

**العطل الحرفيّ:**
```
Unified-link preparation failed:
  …\forex_runtime\atoms: Cannot create a file when that file already exists.
  (×26 لكل مجلّد بـforex_runtime و crypto_runtime)
```

**السبب المقاس:** `forex_runtime/*` و`crypto_runtime/*` تحوي **روابط Junction
معطوبة** موجّهة لمسار قديم محذوف (`Desktop\…\QUANT_NQ_RC5\atoms`) من استخراج
سابق. سكربت `prepare_unified.py` يحاول إنشاء روابط جديدة فوقها فيتصادم، وحذفه
الذاتيّ لا يتعامل مع Junction معطوب على ويندوز.

**الحلّ (يتكرّر مع كل فكّ ضغط جديد):**
```powershell
# إزالة نقاط الربط المعطوبة (rmdir لا يمسّ الهدف)
foreach($runtime in "forex_runtime","crypto_runtime"){
  foreach($n in "atoms","transport","security","clock","catchup","scripts","tools",
                "shared","governance","config","mt5","ctrader","core"){
    cmd /c rmdir "C:\Users\NQ\QUANT_NQ\$runtime\$n" 2>$null
  }
}
# ثمّ إعادة البناء
venv\Scripts\python.exe scripts\prepare_unified.py     # → "26 created"
```
**نُفِّذ 2026-08-28 وأقلع النظام كاملًا (5 منافذ خضراء).**

**السبب الجذريّ:** `publish_private.ps1` كان يسأل سؤالًا واحدًا: «هل `.git`

تتخطّى التهيئة كلّها وتقع في مكان آخر.

**الحلّ الدائم (نُفِّذ):** جُعلت التهيئة **تُصلح نفسها** — كل قطعة تُفحص
وتُصلَح مستقلّة:
| القطعة | التصرّف |
|---|---|
| `.git` | يُنشأ إن غاب |
| `origin` | يُضاف إن غاب · **يُصحَّح إن كان عنوانه خطأ** |
| الهويّة | تُضبط إن غابت |
| التطعيم على تاريخ البعيد | فقط إن لم يوجد كومِت محلّيّ |

**النتيجة:** لا يهمّ من أين تبدأ — يُصلح الناقص ويكمل. أُثبت عمليًّا: دفع نظيف
