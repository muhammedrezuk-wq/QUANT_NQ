# ٥ · ناقل الأحداث — ما يضمنه وما يرفضه

## الضمانات

**عزل المعالجات:** كل معالج يُنفَّذ معزولًا — استثناؤه يُلتقط ولا يمسّ بقيّة المشتركين
ولا الناقل. ولكل تسليم **مهلة** (`dispatch_timeout_s`) فلا يعلّق معالجٌ بطيء الناقلَ كلّه.

**نسخة خاصّة لكل مشترك:** كل مشترك يستلم نسخته المستقلّة من الحمولة، فلا يفسد أحدهم
بيانات غيره.

**إعادة الحالة للمتأخّر:** الناقل يحفظ آخر حدث «حالة» ويعيده فورًا لأيّ مشترك جديد،
فتلحق اللوحة بالحالة الراهنة بلا انتظار الحدث التالي.

**وراثة الأثر:** كل حدث يرث `trace_id` أبيه ويسجّل `parent_event_id` — فتُبنى شجرة
سببيّة كاملة من التِكّة إلى الأمر.

**الختم الزمنيّ:** الناقل يختم كل حدث بالوقت الرسميّ المصحَّح بـ`setdefault` — **يضيف
ولا يعدّل** ما ختمته الذرّة.

## 🔴 حارس الأوامر — أخطر ما في الناقل

```python
# core/event_bus.py
_COMMAND_MARKERS = (
    "order", ".buy", ".sell", ".execute", ".cancel",
    "final_decision", "command", ".submit", ".send",
)

def _is_replayable(event_name):
    return event_name.endswith(_STATE_SUFFIXES) and not _is_command(event_name)
```

**حدث الحالة يُعاد للمشترك المتأخّر. حدث الأمر لا يُعاد أبدًا** — حتى لو سُمّي بلاحقة
حالة بالخطأ.

**السبب:** إعادة أمر تنفيذ تعني **صفقة مزدوجة على حساب حقيقيّ**.
