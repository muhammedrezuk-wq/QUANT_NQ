## الفكرة

تتولى Core الاكتشاف والتحقق ودورة الحياة والنقل، ولا تعرف اسم ذرّة أو رقمها.
السلوك يعيش في ذرّات مستقلة تتواصل بالأحداث. لكل سوق ناقله وعملية Core
المستقلة؛ لذلك عبارة «ناقل واحد» تعني ناقلًا واحدًا **داخل كل runtime**، لا
ناقلًا مشتركًا بين فوركس وكريبتو.

`1b0d0f6b91505984`.

وزرّ غرفة القيادة. **الورق في `docs/docs/` والأزرار في `أزرار التشغيل/`.**

## الإطلاق الرسمي

العقد الرسمي هو زران مستقلان؛ شغّل السوق المطلوب فقط:

- `أزرار التشغيل/تشغيل الفوركس الموحد.bat`: فوركس؛ لوحة `8090`.
- `أزرار التشغيل/تشغيل الكريبتو الموحد.bat`: كريبتو؛ لوحة `8091`.

كل سوق يملك Core وناقلًا ولوحة مستقلة.

**الأزرار كلّها في [`أزرار التشغيل/`](أزرار%20التشغيل):**

| الزرّ | ماذا يفعل |
|---|---|
| `تشغيل الفوركس الموحد.bat` | فوركس — لوحة `8090` · **عقد رسميّ** |
| `تشغيل الكريبتو الموحد.bat` | كريبتو — لوحة `8091` · **عقد رسميّ** |
| `تهيئة المشروع الموحد.bat` | التهيئة أوّل مرّة بعد فكّ الضغط |
| `٧_الاختبارات_الكاملة.bat` | السلّة الكاملة |
| `٠_إيقاف_النواة.bat` | الإيقاف |
| `START_LOCAL.bat` | مشغّل محلّي مجمَّع — **أداة داخليّة/قديمة** |

و**`غرفة القيادة.bat` وحده بالجذر** لأنّه المدخل الذي يفتح لوحة الحوكمة.
هو و`START_LOCAL.bat` و`scripts/launch_unified.py` أدوات داخليّة للتشخيص،
وليست عقد الإطلاق الرسميّ — العقد هو زرّا السوقين.

**تنبيه:** CI يبني الواجهة قبل فحص المشروع. وفي checkout نظيف تُبنى محليًا
بـ`cd governance\\ui && npm ci && npm run build` قبل التهيئة؛ حزمة التسليم
النهائية يجب أن تحمل البناء الجاهز.

## الأمن

طبقة الخزنة موجودة ومفعلة في الإعداد. في **checkout نظيف** يرجع الفحص
`SECURITY_STATE=NOT_CONFIGURED` — لا خزنة ولا مفاتيح، وهي حالة متوقّعة للمصدر.

**على جهاز المالك (مقيس 2026-09-01):** `SECURITY_STATE=READY` ·
`vault_present=True` · `key_count=3` · `secret_values=NOT_DISPLAYED`.
**وهذه ليست جاهزية تشغيل ماليّ** — الجاهزيّة تحتاج إثبات تنفيذ حيّ عبر وسيط.
