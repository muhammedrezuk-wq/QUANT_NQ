# QUANT_NQ_NEWS

بوت تيليجرام عربي لمتابعة ناسداك، مع تقرير صباحي، أخبار، أجندة اقتصادية حقيقية، وإدارة مستخدمين.

مشروع مستقل تمامًا عن QUANT_NQ_V10 — يعمل جنبه على نفس الجهاز، بدون أي اتصال آلي بينهما حاليًا.

## ✅ تحديث ٢٠٢٦-٠٨-٢٥ — الخبر صار يُقرأ، والنشر صار بوقته

أمر المالك: «الناس بدها تقرا خبر وتعرف شي، وبدها روح توصية — توقّعات مع الخبر».

**① شكل الخبر**: الملخّص كان يُسحب من التغذية ويُخزَّن في قاعدة الجسر **ولا يُعرض
للقارئ أبدًا** — صار يُترجَم ويظهر. ومعه الرموز المعنيّة (`USTEC · XAUUSD`) ووقت
النشر الحقيقي ووسم الأثر.

**② سطر «ما يُترقَّب»**: أقرب حدث في تقويم المنصّة ومعه **المتوقّع والسابق**. هذا
توقّع **منشور رسميًّا** لا ترجيح نخترعه — والفرق بينهما هو الفرق بين خبر وإشاعة.

**③ النشر التلقائي**: البوت كان لا ينشر خبرًا من نفسه إطلاقًا، ينتظر ضغطة `/news`.
صار ينشر عالي الأثر مع كل دورة سحب (١٠ دقائق)، بلا تكرار أبدًا، ولا يُختم الخبر
«منشورًا» إلا بعد وصوله فعلًا. **مطفأ افتراضيًّا** — `NEWS_PUSH=on` يشغّله.

**④ خطأ مقيس أثناء البناء**: جوجل ردّ `Error 500 (Server Error)` نصًّا عاديًّا،
فقبله الكود ترجمةً **وخزّنه على القرص** — فوصل الخطأ للطالب مكان الخبر ويُعاد أبدًا.
الآن: حارس يرفض أي مخرج بلا حرف عربي، وذاكرة تنظّف نفسها، **وسلسلة محرّكات**
(جوجل ثمّ بديل مجاني) فلا يبقى الخبر إنجليزيًّا حين يسقط محرّك.

**⑤ اليورو**: مفرداته كانت ثلاثًا (`euro` · `eur/usd` · `ecb`)، فكانت «Eurozone»
و«European Central Bank» و«Lagarde» تسقط «خارج الموضوع» — وقاعدة الجسر فيها صفر
صفّ `EURUSD`. وُسّعت المفردات، وأُضيفت تغذية عملات حيّة (`investing_fx`).

## ✅ إصلاحات ٢٠٢٦-٠٨-٢٤ — سبعة أخطاء مقيسة في المسار الحيّ

١. `/status` كان يقرأ المفتاح `event` بينما جسر الأجندة يسمّيه `title` ⇒ `KeyError` في
   اللحظة التي وُجد لأجلها الأمر بالضبط (عند تفعيل Event Lock)، فيصل «صار خلل» بدل اسم الحدث.
٢. تصنيف الأخبار كان يطابق داخل الكلمات: «US imposes tariffs **against** China» تحمل
   `gain` ⇒ تُصنَّف إيجابية. صارت المطابقة بحدود كلمات مع اللواحق (`gains` · `surging` · `dropped`).
٣. رسائل الأجندة كانت تُختم «مُرسَلة» **قبل** إرسالها ⇒ سقوط الشبكة يضيّع التنبيه للأبد.
   الآن `mark_sent()` تُنادى بعد وصول الرسالة فعلًا، وإلا أُعيدت المحاولة بالدقيقة التالية.
٤. التقرير الصباحي كان يُبنى داخل حلقة البوت (سحب سبع تغذيات + ترجمة) فيجمّد كل المستخدمين
   ثوانيَ عدّة — صار بخيط منفصل عبر `asyncio.to_thread`.
٥. عدّاد «جديد» في كتابة الجسر كان يعدّ التحديث إدراجًا (`ON CONFLICT DO UPDATE` يُرجع
   `rowcount=1`) فتقول الحالة «جديد ٣٠» بعد كل سحبة — صار يفصل الجديد عن المُكمَّل.
٦. لوحة `/health` كانت تعرض «آخر خطأ: لا يوجد» **دائمًا** لأنّ لا أحد يكتب `last_error`
   في المسار الحيّ — الآن يكتبه حارس الأوامر ومهامّ المجدول.
٧. ملفّات الحالة (`users.json` · `system_state.json` · …) كانت تُكتب فوق نفسها مباشرة ⇒
   انقطاع وسط الكتابة يتركها مبتورة. صارت كتابة ذرّية (`app/jsonio.py`).

ومعها: تدوير السجلّ (كان ٣ ميغا بلا حدّ)، وإسكات سطري `apscheduler` في الدقيقة،
و١٦ اختبارًا جديدًا في `tests/test_step3_live_path.py` تغطّي المسار الحيّ (كان بلا اختبار).

## ✅ إصلاحات الإصدار السابق — أربعة أخطاء حقيقية كانت تمنع البوت من العمل إطلاقًا

كل وحدة منها اتفحصت وأُصلحت واختُبرت فعليًا (مو بس "افتراض إنها اشتغلت"):

1. **`app/routing_service.py` كان غير موجود بالمشروع كله.** البوت كان ينهار فور التشغيل
   (`ModuleNotFoundError`) قبل حتى ما يتصل بتيليجرام. تمت إضافته بمنطق حقيقي (فلترة حسب
   كلمات مفتاحية ذات صلة بناسداك/الأسواق).
2. **`AnalysisService.analyze_news_item()` كانت مفقودة.** أمر `/news` كان ينهار عند أول
   محاولة عرض خبر. تمت إضافتها.
3. **`CalendarService.is_event_lock_active()` و`get_active_lock_event()` كانتا مفقودتين.**
   أوامر `/status` و`/health` كانتا تنهاران. تمت إضافتهما.
4. **`AnalysisService.build_bias_summary()` و`CalendarService.get_top_event_summary()`
   كانتا مفقودتين.** التقرير الصباحي (الميزة الأساسية المجدولة يوميًا) كان ينهار بالكامل.
   تمت إضافتهما.

**باگ خامس حقيقي لُقِط أثناء الإصلاح:** فحص الكلمات المفتاحية (إيجابي/سلبي) كان يُطبَّق على
النص **المُترجَم للعربي**، بينما قائمة الكلمات المفتاحية بالإنجليزي بالكامل — يعني كل خبر كان
يُصنَّف "محايد" دائمًا بصمت، بغض النظر عن محتواه الفعلي. تم تصحيحه ليفحص النص الإنجليزي الأصلي.

## ✅ الأجندة الاقتصادية — من تقويم ميتاتريدر، بلا مفتاح API

المصدر الحالي هو جدول `calendar` داخل قاعدة الجسر التي يكتبها الإكسبرت على المنصّة
(`app/calendar_bridge.py`). ميزته على Finnhub: العناوين تصل **مترجمة عربيًّا** من المنصّة،
ومعها العملة والأهمية والمتوقّع والسابق والفعلي — **بلا مفتاح ولا اشتراك**. القراءة
**للقراءة فقط** (`mode=ro`)، فالبوت لا يكتب في قاعدة الجسر إطلاقًا.

**وإن غابت قاعدة الجسر، الأجندة تقول ذلك صراحة — ما بترجع بيانات وهمية أبدًا.**

## المزايا الحالية
- بوت تيليجرام عربي
- إدارة مستخدمين وصلاحيات
- تقرير صباحي يومي مجدول (يشتغل بالكامل الآن)
- أمر لعرض الأخبار `/news` (يشتغل بالكامل الآن)
- أمر لعرض الأجندة `/calendar` — **من تقويم ميتاتريدر عبر قاعدة الجسر**
- نشر تلقائي للأحداث بوقتها: تنبيه قبل الحدث بـ`CAL_ALERT_MINUTES`، ونتيجة عند صدورها
- Event Lock حقيقي: `/status` و`/health` بيعرضوا لو في حدث اقتصادي عالي الأهمية خلال ±15 دقيقة
- أمر لإظهار المعرّف `/id`
- سجل logs
- تخزين محلي للمستخدمين والإعدادات

## الإعداد
1. ثبّت Python 3.12.
2. أنشئ بيئة افتراضية:
   ```bash
   py -3.12 -m venv .venv
   .venv\Scripts\activate
   ```
3. ثبّت المتطلبات:
   ```bash
   pip install -r requirements.txt
   ```
4. انسخ `.env.example` إلى `.env` ثم عدل القيم — التوكن ورقمك، ومتغيّرات الأجندة
   (`NQ_BRIDGE_DB` · `CAL_CURRENCY` · `CAL_MIN_IMPACT` · `CAL_ALERT_MINUTES`).
5. شغّل البوت:
   ```bash
   python main.py
   ```

## 📦 الفرع الميت — نُقل إلى الأرشيف (٢٠٢٦-٠٨-٢٤)
خطّ `news.db` كاملًا (`app/rss_writer.py` · `app/db/` · `db/schema/` · `tools/probe_rss.py`
واختباراته الـ٨١) ونسخة الأجندة القديمة (`app/calendar_service.py` بـFinnhub) — كلّها غير
موصولة بـ`main.py` — نُقلت إلى:

    %USERPROFILE%\Desktop\أرشيف_QUANT_NQ_NEWS_الفرع_الميت_2026-08-24

وفيها `اقرأني.md` يشرح ما نُقل ولماذا، وأوامر إعادته إن لزم.

**`data/news.db` بقي مكانه عمدًا**: الذرّة `615_جسر_مصدر_الأخبار` في مشروع `QUANT_NQ`
حيّة (`startup_mode: auto`) وتشير إليه صراحةً. لكن بعد أرشفة كاتبها صارت القاعدة مجمّدة
على بيانات ٢٠٢٦-٠٨-٢٠ — والذرّة ٦١٦ هي التي تقرأ المسار الحيّ (`nq_brain.db`).
