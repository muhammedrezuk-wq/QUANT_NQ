# 🌳 النسختان — أيّهما تعمل ولماذا

**٢٠٢٦-٠٩-٠٥ · حكم المالك:** «مشكلتي إنكم ما لكم شارحين شو سبب وجود نسختين،
ولا عم تعرفوا تستخدموهم، ولا في معرفة أي نسخة شغّالة منهم».

هذه الورقة تجيب بالدليل المادي لا بالرأي. **الدليل:** ملفات `__pycache__` —
بايثون لا ينشئها إلا لملف **نُفِّذ فعلًا**، وتاريخها هو تاريخ آخر تنفيذ.

## ٢. لماذا وُجدت نسختان أصلًا؟

`forex_runtime/` أُنشئ **٢٠٢٦-٠٨-٢٧/٢٨**. والسبب شقّان، أحدهما مبرَّر
والآخر عرَض جانبي:

### (أ) مبرَّر — عزل بيانات السوقين

```
forex_runtime/var/    2,710 MB   ← alerts · audit · store · logs ·
crypto_runtime/var/               governance · reconciliation · telemetry
```

كل سوق يحتاج قاعدته وسجلّاته وخزنته وسجلّ مطابقته منفصلًا. لو اشتركا
لاختلطت صفقات الفوركس بالكريبتو في المطابقة والحسابات. **هذا العزل صحيح،
وهو الشيء الفريد فعلًا في `forex_runtime` (لا نظير له في الجذر).**

### (ب) غير مبرَّر — نسخ الكود

عزل **البيانات** لا يستلزم نسخ **الكود**. والسبب الفعلي:

```python
scripts/run_forex.py:23   os.chdir(ROOT / "forex_runtime")
scripts/run_forex.py:28   QUANT_ATOMS_ROOT = forex_runtime/atoms
```

المقلع ينتقل بمجلّد العمل إلى مجلّد السوق، فصار كل مسار نسبيّ يبحث هناك —
فنُسِخ الكود إلى جانب البيانات لتعمل المسارات. **حلُّ مسارات، لا قرار
معماري.** والدليل أن `forex_runtime/core` نُسخ ولم يُنفَّذ قط.

والنسخ ناقصة أصلًا، لا مرايا كاملة:

| المجلد | الجذر | forex_runtime |
|---|---|---|
| `core` | 47 ملف | 24 |
| `shared` | 56 | 33 |
| `governance` | 252 | 240 |
| `atoms` | 1,428 | 1,428 (مطابق تمامًا) |

## ٣. كيف تُستخدم — القاعدة العملية

1. **الذرّات:** عدّل في `atoms/` ثم **انسخ إلى `forex_runtime/atoms/`**.
   بلا النسخ، النظام يشغّل القديم بصمت.
2. **`shared/`:** الجذر هو العامل — لكن الوحدات الثلاث المزدوجة أعلاه
   يجب مزامنتها أيضًا.
3. **`core/`:** الجذر فقط. لا تعدّل `forex_runtime/core` — نسخة ميتة.
4. **`var/`:** لا يُنسخ ولا يُزامَن — بيانات السوق الحيّة، خارج git.

**التحقّق قبل أي تشغيل:**

```powershell
Get-ChildItem 'atoms' -Recurse -Filter '*.py' | ForEach-Object {
  $t = $_.FullName -replace '\\atoms\\', '\forex_runtime\atoms\'
  if ((Get-FileHash $_.FullName).Hash -ne (Get-FileHash $t).Hash) { "DIFF: $($_.Name)" }
}
```

آخر قياس (٢٠٢٦-٠٩-٠٥ ٢٢:٤٠): **503 ملف متطابق · صفر مختلف** — والشجرتان
مدفوعتان إلى المستودع متطابقتين.

## ٤. الحجم — الرقم الذي يُفاجئ

## ٤·٥ — التوحيد المنفَّذ (٢٠٢٦-٠٩-٠٥ ٢٢:٥٣)

**حكم المالك:** «لا هيك، لازم يكون في نسخة وحدة بس».

**التغيير — سطر واحد في `scripts/run_forex.py`:**

```python
- QUANT_ATOMS_ROOT = ROOT / "forex_runtime" / "atoms"
+ QUANT_ATOMS_ROOT = ROOT / "atoms"
```

**الدليل المقيس بعد الإقلاع:**

| الشجرة | pyc | آخر تنفيذ | الحكم |
|---|---|---|---|
| `atoms/` | **268** | 22:53:14 | ✅ العاملة وحدها |
| `forex_runtime/atoms/` | 255 | 22:32:19 | ⏸ متجمّد — لم يُلمس |
| `forex_runtime/shared/` | 3 | **لم يتغيّر** (00:23 · 21:12) | ⏸ لم تُحمَّل |

**زال الازدواج:** لا وحدة محمَّلة مرّتين بعد اليوم. مصدر واحد للكود.

**ما لم يتغيّر:** عزل البيانات كما هو — `var/` والحالة الحيّة وسجلّ
المعايرة تحت الـruntime. العزل كان دائمًا في البيانات لا في الكود.

**الحارس:** `check_path_authority` يفحص تطابق النسخ ويرفض الإقلاع عند
الانحراف (جرّبناه: كشف انحراف `run_forex.py` فورًا حتى زُومن). فالمرآة
`forex_runtime/atoms` تبقى للفحص لا للتنفيذ — ولو نُسيت المزامنة اليوم،
يعمل النظام بالكود **المعدَّل** لا بالقديم، ويصيح الحارس. أي أن الخطر
تحوّل من صامت إلى مُعلَن.

**نتيجة الفحوص بعد التوحيد:** 🟢 `check_path_authority` سليم ·
`test_build_registry` ١٥ اختبارًا تمرّ · النظام حيّ (622 · 618 · 613 ·
101 كلها healthy).

## ٥. الخلاصة بثلاث جمل

1. **الذرّات تعمل من `forex_runtime/atoms`**، و**النواة من الجذر**،
   و**`shared` من الاثنتين معًا** — وهذا الخلط هو الخطر، لا التكرار نفسه.
2. **`forex_runtime/core` نسخة ميتة** لم تُنفَّذ قط.
3. سبب النسخ ليس معماريًّا بل `chdir` في المقلع؛ والعزل الحقيقي المطلوب
   هو `var/` وحده.
